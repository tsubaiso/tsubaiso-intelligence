# process-map — 導入工程マップと層2の呼び出し

導入は **トライアル（サンプルデータ）→ Sandbox（開発／運用テスト）→ 本番** の順に進む。各工程で本スキルが順序づけて呼ぶ層2能力・参照する判断層を示す。工程進行そのものは書込を伴わず、実作業は各層2能力が担い、org 書込は必ず ti-core の安全ゲート（`safety-gate.md`）を通す。

## PSA 7工程マップ

```
計画・管理 → 設計 → 制作（カスタマイズ） → 構築・設定 → データ移行 → 教育 → 運用テスト
```

| 工程 | 進行での主眼（AI リード／支援） | 呼ぶ層2・参照する判断層 |
|---|---|---|
| 計画・管理 | 標準スケジュール雛形からタスク分解・進捗確認・再計画 | 導入ナレッジ（Knowledge）・本スキル内の段取り |
| 設計 | 業務モデルの図式化・サンプルデータ運用シミュレーション・重要マスタ設計・承認/権限設計 | ti-reference（構造・意味・Fit&Gap 集計）・ti-spec-view（現状カスタマイズ可視化）・Atlas（意味定義）。詳細は `design-lead-loop.md` |
| 制作（カスタマイズ） | メタデータ改修・帳票の作成/調整。実装形態の判断が要る瞬間は ti-lifecycle を参照 | ti-metadata（配備機構）・ti-report（帳票）／判断＝ti-lifecycle 参照 |
| 構築・設定 | 構築手順書の生成・設定移行の支援 | ti-metadata（機構）・Knowledge |
| データ移行 | マスタ設定・仕掛かりトランザクション移行。大量 I/O はスクリプト経路（下記） | ti-data-load（投入・移行機構・dry-run→突合） |
| 教育 | 業務モデルからマニュアル草案の生成 | Knowledge・導入ナレッジ |
| 運用テスト | テストシナリオ・課題表の整理、課題解決（運用変更／カスタマイズ）の支援 | ti-update（入力支援・運用テストの実データ操作）／課題がカスタマイズなら制作工程へ戻す |

> 表中の「導入ナレッジ（Knowledge）」「Knowledge」は層0のツバイソナレッジ基盤／isoppy 等の導入知識を指すが、**具体的な呼び先の結線は後続**（層0基盤の整備・改名発効後に確定）。現時点では段取り上の参照点として置き、実体が結線されるまでは人の導入知識・既存資料で代替する。

## 制作・構築での ti-lifecycle 参照（進行→判断）

制作・構築工程で「この要件をどの実装形態で作るか」の判断が要る瞬間は、判断層 ti-lifecycle の `references/implementation-form.md`・`dev-phase-playbook.md` を発火点で参照する。**本スキルは実装形態を自ら決めない**（判断は ti-lifecycle が正本・進行スキルは工程の中で呼び出すだけ）。ti-lifecycle が形態を決めた先の配備は ti-metadata の機構へ接続する。

## 大量 I/O はスクリプト経路

マスタ設定・データ移行・帳票生成など大量データ I/O は、逐次呼び出しではなく雛形から生成したローカル実行スクリプトで行う（操作経路選択＝ti-core 群A）。スクリプトは意味定義で正しい項目・関係・マスタ取得を用い、**dry-run→突合**を伴う（機構は ti-data-load）。この経路選択を前提にデータ移行工程で ti-data-load を呼ぶ。

## ERP 工程の差分

ツバイソ ERP は工程が一部異なる。

```
仕訳分析 → マスタ設計 → システム設定 → マスタ設定/残高設定 → 教育 → 運用テスト
```

- **仕訳分析**: 債権債務対象取引の洗い出しと使用モジュール分類（PSA にはない前段工程）。
- **マスタ設計**: 勘定科目体系・原因マスタの関連付け。PSA 連携時はマスタ体系の整合を取る。
- 以降（システム設定・残高設定・教育・運用テスト）は PSA と同型に AI がリードする。

ERP 工程の各段の詳細マッピングは拡充対象（本 reference は PSA との差分＝仕訳分析の追加とマスタ設計の会計軸を示すに留める）。

## 環境進行の原則

トライアル＝サンプル中心・破棄前提、Sandbox＝開発と運用テスト、本番＝全量移行後の本稼働。工程が制作・構築・データ移行へ進むほど書込先 org の実害が大きくなるため、書込前は必ず現在の環境を確認し、本番反映は checkonly 先行＋承認を通す（`mode-and-handoff.md`／ti-core `safety-gate.md`）。
