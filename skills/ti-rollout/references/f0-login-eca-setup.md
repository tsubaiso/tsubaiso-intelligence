# 旧バージョン向けログイン ECA のセットアップ（管理者・組織で1回）

PSA のパッケージにログイン用の外部クライアントアプリケーション（ECA）が含まれていない組織で、**同じはたらきをする ECA を組織内に手動で 1 つ作る**手順。作るのはこの 1 つだけで、PSA 本体のバージョンアップは要らない。

**この ECA は §4 の api スコープ ECA（`api-eca-setup.md`）とは別物**。用途・OAuth 範囲・シークレットの要否がすべて違うので、片方の設定値をもう片方へ流用しない。

| | 本手順の ECA | api スコープ ECA |
|---|---|---|
| 用途 | TI のログイン基盤への Salesforce ログイン | ローカルスクリプト実行の本人接続 |
| コールバック先 | TI のログイン基盤（当社ホスト） | `http://localhost:1717/OauthRedirect` |
| OAuth 範囲 | `openid` `api` `refresh_token` | `api` `refresh_token` |
| シークレット | **必要**（当社へ預ける） | 使わない |
| PKCE | **要求しない** | 要求する |

## 1. 対象かどうかの判定

**PSA のバージョン番号で判定しない。** 判定は「**パッケージ同梱のログイン用 ECA が組織にあるか**」で行う。組織のメタデータから外部クライアントアプリケーションを一覧し、PSA 名前空間のログイン用 ECA が見つかれば本手順は不要で、通常のログイン URL を案内する。見つからなければ本手順の対象。

同梱 ECA の一部の設定（グローバル OAuth 設定・ポリシー）はパッケージ分が購読側の一覧に出ないため、**存在の有無だけを判定材料にする**。設定内容の読み取りはできない前提で進める。

## 2. 全体の流れ

| 順序 | 作業 | 担当 |
|---|---|---|
| 1 | 組織 ID（18 桁）を確認し、コールバック URL とログイン URL を組み立てる | AI |
| 2 | ECA を作成する | 管理者（AI が設定値を用意） |
| 3 | コンシューマ鍵とコンシューマの秘密を取得する | 管理者 |
| 4 | 2 つの値をサポートチケットで当社へ渡す | 管理者 |
| 5 | 当社の管理画面へ登録する | 当社 |
| 6 | ログイン URL で接続を確認する | 管理者 |

**手順 1 を管理者にやらせない。** 必要なのは 18 桁の組織 ID だが、Salesforce の「会社の情報」画面は 15 桁を表示する。桁の変換を管理者に求めると必ず詰まる。AI が組織 ID を取得し、URL を組み立てて渡す。

## 3. 組織 ID と URL の組み立て（AI）

組織 ID は組織情報の照会で 18 桁のまま得られる。15 桁を見つけて変換するのではなく、**18 桁を返す経路で取る**。

| 用途 | 形 |
|---|---|
| コールバック URL | `{ログイン基盤のホスト}/login/oauth2/code/legacy-{18桁の組織ID}` |
| ログイン URL | `{ログイン基盤のホスト}/login/legacy/{18桁の組織ID}` |

`{ログイン基盤のホスト}` は当社のサービスホストで、組織ごとに変わらない。**値を推測して組み立てない**——サポートからの案内、または管理者が受け取っている接続情報から取る。本番組織とサンドボックスでは接続先の Salesforce が変わるが、**URL の形は同じで、区別は組織 ID で付く**。

組み立てた 2 本の URL は、ECA 作成前に管理者へ渡す（コールバック URL は §4 の入力に使い、ログイン URL は §7 の確認と利用者への案内に使う）。

## 4. ECA を作成する

設定 → クイック検索「外部クライアント」→「外部クライアントアプリケーションマネージャー」→「新規外部クライアントアプリケーション」。

| 項目 | 値 |
|---|---|
| 外部クライアントアプリケーション名 | `Tsubaiso F0 Login` |
| API 参照名 | `Tsubaiso_F0_Login` |
| 取引先責任者 メール | 管理者のメール |
| 配信状態 | ローカル |

- 「API (OAuth 設定の有効化)」を展開 →「OAuth を有効化」にチェック
- コールバック URL: §3 で組み立てた値をそのまま貼る（末尾まで完全一致が要る）
- OAuth 範囲（3 つ）: 「基本情報の実行 (openid)」＋「API を使用してユーザーデータを管理 (api)」＋「いつでも要求を実行 (refresh_token, offline_access)」
- セキュリティ（チェックを**入れたまま**）: 「Web サーバーフローの秘密が必要」「更新トークンフローの秘密が必要」。この接続はシークレットを使う認可コードフローで、外すと当社側の設定と合わない
- セキュリティ（チェックを**外す**）: 「Proof Key for Code Exchange (PKCE) 拡張を要求」。当社側はシークレットで認証しており PKCE の値を送らないため、要求すると認可が通らない
- 作成（利用可能まで最大 30 分）

**api スコープ ECA とチェックの向きが逆**（あちらは PKCE を要求しシークレットを外す）。片方の手順を見ながらもう片方を作ると必ず取り違えるので、本表のとおりに入れる。

### メタデータデプロイで作る場合

ECA はメタデータデプロイでも作成できる（4 つの構成要素を 1 回にまとめて送る。制約は `api-eca-setup.md §注意` と共通）。ただし**本手順で省けるのは入力の手間だけ**で、次の 2 つは残る。

- **コンシューマの秘密はメタデータで取り出せない。** §5 で管理者が画面を開いて控える必要がある
- コールバック URL は組織ごとに違うため、雛形の使い回しでは通らない（§3 の値へ差し替える）

デプロイを選ぶ場合も、**org へ送る前に承認ゲートを通す**（ti-core `references/safety-gate.md`）。デプロイが通らないときは §4 の画面手順へ切り替える。

## 5. コンシューマ鍵とコンシューマの秘密を取得する

作成した ECA の「設定」タブ →「OAuth 設定」→「コンシューマー鍵と秘密」（本人確認コードの入力を求められることがある）→ **コンシューマ鍵**と**コンシューマの秘密**の 2 つを控える。

**この ECA では鍵と秘密の両方を当社へ渡す。** api スコープ ECA では秘密を使わないため鍵のみだが、本手順は逆になる。

## 6. 当社への受け渡し

**サポートチケットで渡す。** コンシューマの秘密はパスワードと同じ性質の情報なので、メール・チャットの本文に平文で書かせない。

- 渡すもの: コンシューマ鍵、コンシューマの秘密、対象組織（本番／サンドボックスの別）
- **AI は秘密を会話へ書き出さない・保存しない・中継しない。** 管理者が自分でチケットへ貼る。AI が案内するのは「どこへ、何を、どの経路で」までにする

当社側で登録するまでログインはできない。登録完了はチケットで通知される。

## 7. 接続を確認する

登録完了の通知後、§3 のログイン URL を開き、管理者本人の Salesforce アカウントでログインする。ログイン画面が出てアクセス許可後に接続できれば完了。

以降、TI を使う各利用者にも**このログイン URL を案内する**（通常のログイン URL は使えない）。PSA を同梱 ECA が入るバージョンへ更新した時点で、通常のログイン URL へ切り替えられる。

## 8. 詰まりどころ（切り分け）

| 症状 | 原因 | 対処 |
|---|---|---|
| ログイン URL が 404 になる | 当社側で鍵の登録が済んでいない／組織が有効な状態でない | §6 のチケットの状況を確認する。登録前は 404 が正常な挙動 |
| ログイン URL が 404 になる（登録済みなのに） | URL の組織 ID が 15 桁になっている、または別組織の ID | §3 のとおり 18 桁で組み立て直す |
| `redirect_uri_mismatch` | ECA のコールバック URL と当社側の値が不一致（末尾まで完全一致が必要） | §3 の値と ECA の登録値を突き合わせる。`legacy-` の後の組織 ID の桁も確認する |
| 認可画面までは出るが戻ってきてエラー | 「PKCE 拡張を要求」にチェックが残っている | §4 のとおり外す |
| トークン取得で認証に失敗する | 「Web サーバーフローの秘密が必要」を外している、または当社へ渡した秘密が違う | チェックを入れ直し、§5 の秘密を取り直してチケットで渡す |
| 認可後に権限のエラーが出る | OAuth 範囲に `openid` が入っていない（利用者の識別に要る） | §4 の 3 つが選ばれているか確認する |
| 作成直後に認証が通らない | ECA が利用可能になるまで最大 30 分かかる | 待って再試行する |
| 別組織で作った ECA の鍵を使い回した | ローカル配信の ECA の鍵は作成した組織でしか有効でない | 対象組織で作り直す |

## 9. この設定の位置づけ（管理者へ伝えること）

- 作るのは**貴社の Salesforce 上の設定**で、無効化・削除はいつでも貴社の操作でできる
- AI が参照できるのは**ログインした利用者本人の権限の範囲内**。この設定で参照範囲は広がらない
- 業務データは貴社の組織内にとどまる
- 同梱 ECA が入るバージョンへ PSA を更新した時点で**この設定は不要になる**（一時的な措置）

## 停止

ECA の無効化・削除、または当社側に登録した鍵の削除で、この経路のログインを止められる。
