# 使い始めの練習 — 接続を終えた利用者が、頼み方を一通り試す

接続を終えた利用者が、最初の十数分で TI への頼み方を一通り試し、その後は自分の業務の言葉で依頼を組み立てられるようにする。**練習で使う依頼文・成功の判定・注意書きは、すべて公開の利用ガイドにある。本 reference が持つのは進め方だけ**で、ガイドの中身を写さない。

## いつ始めるか

| きっかけ | ふるまい |
|---|---|
| 利用者が「TIの使い方を教えて」「TIは何ができるの」「練習したい」「最初に何をすればいい」のように、**TI そのものの使い方**を尋ねた | 練習を始める |
| 利用者フロー 3 または §3 step 8 の疎通確認が成功した | 練習を1行で提案する。断られたら終える（押し付けない） |
| 練習の外で、製品（PSA/IMA）の機能・操作・仕様を尋ねた（「請求書はどう発行しますか」） | 練習ではない。ti-howto へ渡す |

このセッションで §0 の注意（プランとプライバシー）をまだ提示していなければ、練習に入る前に提示する。練習では業務データを扱うため。

## 中身は利用ガイドから引く [REQUIRED]

- 材料は、公開ヘルプセンターの記事「**Tsubaiso Intelligence利用ガイド（全利用者共通）**」の §5 到達確認（確認1〜5）・§6 TIのしくみ・§7 依頼文の例。**ナレッジでこの記事を引いて読み、依頼文・成功の判定・注意書きは記事の記載をそのまま使う。**
- **記事の節は、番号でなく見出しの名前で特定する。** 本 reference の §番号は、記事の改訂で番号がずれたときに違う節を読みに行かないよう、見出しの名前と併せて書いている。番号と名前が合わなければ、名前のほうを採る。
- **本 reference と回答に、依頼文の例を自分で作って足さない。** 記事を改訂すれば練習の中身も変わる形を保つ（写した例文は記事の改訂に追従しない）。
- **記事を引けないときは、練習に入らない。記事の本文を推測で再現しない。** 引けない理由で分ける。
  - ナレッジのツールが無い・呼び出しが失敗する：ナレッジへの接続が済んでいない。利用者フローの該当する接続へ戻る
  - ツールは応答するが記事が見つからない：見つからなかったことを利用者へ伝え、ti-core `references/support-escalation.md` へ回す

## 進め方 [REQUIRED]

**1つ進めるごとに、利用者の結果を待つ。** まとめて示さない。

**練習の途中に利用者が入力した依頼文には、通常の依頼として、該当するスキルで応答する**（ナレッジの検索なら ti-howto、集計なら ti-reference のように）。応答のあとに、練習の続きとして成功の判定と次の案内を添える。練習の途中の依頼文は、上の「いつ始めるか」の振り分けの対象にしない（確認2のように製品の使い方を尋ねる依頼文でも、練習を終えない）。

1. **始める前に**: 練習の目的（頼み方を一通り試す）・所要の目安（十数分・途中でやめてよい）・流れを3行以内で示し、次の2つを尋ねる。担当業務（営業・プロジェクトの管理・経理など。ガイドの §7 から例を選ぶため）と、レコードの更新の権限があるか（参照のみか）。
2. **ガイドの確認1〜4**: 1つずつ、記事の依頼文を示し、**利用者自身に入力してもらう**。AI が依頼文を入力したことにして先に実行しない（入力すること自体が練習）。応答のあと、記事の成功の判定に当て、何が起きたか（どの接続先から何を得たか）を1〜2文で伝えて次へ進む。**省いてよいのは、このセッションで実際に呼び出しが成功した接続先の分だけ**（利用者フロー 3 で確かめたのは PSA/IMA の接続だけなので、ナレッジ・アトラスを呼び出していなければ確認1は省かない）。
3. **ガイドの確認5（更新）**: 手順1で更新の権限があると答え、試したいと答えたときだけ行う。参照のみなら、記事のとおり確認4で準備は完了と伝えて省く。ねらいは、**実行の前に対象と変更内容が示され、承認してから動く**という TI の作法を体験してもらうこと。テスト用のレコードの指定・元の内容へ戻すことは、記事の注意書きに従う。更新は通常どおり ti-reference の書込前ゲートを通る。
4. **しくみとコツ**: ガイドの §6-1（日常の業務で使うスキル）を、ここまでの依頼と結び付けて短く伝える。続けて §6-3（意図した結果にならないとき）を、記事の文言どおり伝える（意図した結果にならないときは、依頼文の冒頭で、ツバイソインテリジェンスのスキルを使うよう伝える）。
5. **ガイドの §7 の依頼文の例**: 表から、手順1で聞いた担当業務に合う2〜3件を選び、1件ずつ試してもらう。期間・集計の単位は、記事のとおり利用者の組織のデータに合わせて変えてよい。該当するデータが無ければ期間を広げる。選び方は次のとおり。
   - **調べる・集計する行を先に選ぶ**
   - **登録・更新の行**は、更新の権限があり、利用者が試したいと答えたときだけ選ぶ。業務で使っている組織では、練習のためにレコードを新しく作らない（記事の確認5の注意書き）。トライアル環境のように試用のための組織では、作成を試してよい
   - **文書の添付が要る行**は、利用者の手元に試せる文書があるときだけ勧める
   - **【先行提供】の行**は、利用者の環境で使えると分かっているときだけ選ぶ
6. **締めくくり**: ここまでの依頼の形を1行で振り返り、ここからは自分の業務の言葉で頼めばよいこと、困ったときはガイドの §9 うまくいかないときの確認事項・§10 困ったとき・お問い合わせ を見ればよいことを伝える。

## やらないこと

- 業務で使っている組織で、練習のためにレコードを新しく作らない・削除しない（ガイドの確認5の注意書き）。
- 練習の結果を採点しない。うまくいかなかったときは、ガイドの §9 うまくいかないときの確認事項 に沿って原因を切り分ける。解けなければ ti-core `references/support-escalation.md`。
- ガイドに無い機能・依頼文を練習に入れない。
