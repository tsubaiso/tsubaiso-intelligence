# firing-observation — 先行手順を踏んだかを記録から数える

規約が「Xの前にYを引く」と定めても、**引かなかったことは痕跡を残さない**。証跡を出す担い手が引くべき本人と同じなので、引き忘れた応答は正常系と一文字も変わらない。本書は、その不発をセッション記録から**事後に**数えるための作法を定める。

**予防ではなく観測。** 事故そのものは止まらない。止まらない代わりに、**規律が実際に効いているかを数字で確かめられる**ようになる。

## 機械化できる発火の境界

判定できるのは2層まで。

| 層 | 問い | 判定 |
|---|---|---|
| L1 事象の有無 | その操作・その主張が記録に在るか | できる |
| L2 事象の対の成立 | Aが在るなら、その前にBが在るか（順序と対象の一致つき） | できる |
| L3 内容への従属 | Bの返りの**中身に従って**Aを行ったか | **できない** |

したがって発火点は「**トリガ事象 → 先行必須事象**」の形でしか宣言できない。痕跡に残る引き金は**外に出る操作**（ツール呼出し）と**応答本文**の2つだけで、「〜する瞬間」「〜を検討するとき」は宣言できない。

**L3が残す穴を対で書く。** 引いたが返りに従わなかった回は通り抜ける。穴として塞ごうとすると際限がないので、境界として受け入れる。

## 宣言の書き方（`firing_points.yml`）

```yaml
- id: write_seam_before_record_write
  severity: violation          # violation = 不発を終了コードへ反映 / advisory = 列挙のみ
  trigger:
    tool: ["createSobjectRecord$"]      # 正規表現。名前空間を除いた末尾で当てる
    # text_all: ["語A", "語B"]          # 応答本文の共起（post でのみ成立）
  requires:
    tool: "atlas_write_seam$"
    scope: session             # session = それ以前すべて / turn = 同じ turn 内だけ
    same_object: true          # 対象オブジェクトの一致を要求する
    # read_path: "safety-gate" # 読込ツールが触ったパスで判定する
  message: "..."
  owner: "..."                 # 正本の在処
```

**偽陽性が避けられない判定は`advisory`に置く [REQUIRED]。** 恒常的に鳴る統制は、通す側が件数を見て読み飛ばす運用になり、**本当に直すべき指摘がその中に埋もれる**。掛けた回でNGの大半が同じ1カテゴリだったら、対象でなく**宣言の射程**を先に疑う。

**対象オブジェクトの照合は名前空間を剥がして行う。** 実測（2026-09-14）で`atlas_write_seam`の`target`は`{名前空間}__{接頭辞}{オブジェクト}__c`／`{接頭辞}{オブジェクト}__c`／`{オブジェクト}__c`の3形が混在していた——**同じオブジェクトでも呼出し側によって表記が変わる**。完全一致にすると、実際には引いた回まで不発として数える。

## 実行

```bash
# 観測の起点（2026-08-01）以降を走査する
python3 skills/ti-core/scripts/check_firing.py --mode post

# 宣言を足す・直したら、陽性・陰性・未判定の3側を必ず測る
python3 skills/ti-core/scripts/check_firing.py --selftest
```

終了コードは`0`＝不発なし／`1`＝不発あり／`2`＝**未判定**／`3`＝引数エラー。**`2`を`0`と同じに扱わない**——ホスト実行できない環境では「検査していない」のであって「問題が無い」のではない。

## 読み方

| 出力 | 意味 |
|---|---|
| 母数 | トリガ事象が起きた回数。**これが出ることが本質**で、「発火していない」と「該当場面が来ていない」を分ける |
| 発火率0% | 宣言の条件か置き場の誤りをまず疑う。統制の不全と決めつけない |
| 母数0 | トリガが起きていないか、宣言が当たっていない |
| 未判定 | 対象が取れず判定できなかった回。**発火にも不発にも混ぜない** |

**鳴った側も実体を開く [REQUIRED]。** 出力は「検出した」であって「対象が誤っている」ではない。新設直後の宣言は、自分の誤りと対象の誤りを分ける材料をまだ持っていない。実測でも、初回の「発火率0%」は記録の時刻がUTCで日付の切り方が地方時とずれていたこと、次の「0%」は観測の起点より前の記録だったことが原因で、**どちらも統制の側の誤りだった**。

## 利用者のデータの扱い [REQUIRED]

- 本スクリプトは**記録を読むだけで外へ送らない**
- `events.jsonl`にも業務データ（項目の値・本文）を入れない。残すのは発火点ID・状態・対象オブジェクトのAPI名・時刻・セッションのハッシュだけ
- **観測は任意**。ホスト実行の手段が無い環境では走らない。必須にすると実行不能な必須手順になる
