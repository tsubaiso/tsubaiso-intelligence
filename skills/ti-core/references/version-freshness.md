# 版の鮮度の自己診断（version-freshness）

利用者は、自分の手元に入っているスキルが最新かどうかを気にしなくてよい。**古いまま使っていることに、AI の側が気づいて伝える。**

## なぜ要るか

配布は多段になっている。ツバイソが発行する → 顧客の受け皿へ取り込む → 組織のマーケットプレイスが同期する → 利用者の端末へ届く。**どの段で止まっても、利用者の画面には何も出ない。** 止まっていることが分かるのは、誰かが「できるはずのことができない」と言い出したときだけになる。

しかも古い版の症状は「機能が無い」ではなく、**「AI がその機能を知らないので、できないと答える」**という形で出る。利用者から見ると仕組みの不足ではなく能力の限界に見えるため、更新すれば解決すると気づけない。実際に、承認の代行に対応した版が発行されてから 2 週間、配布が止まっていたのに誰も気づかなかった事例がある（利用者が「承認が許されていない」と申告してはじめて発覚した）。

## いつ読むか

**そのセッションで TI のスキルを最初に使うとき、1 回だけ。** 依頼の内容を問わない。1 セッションで 2 回以上は照合しない。

## 手順

### 1. 自分の版を読む

同梱の `.claude-plugin/plugin.json` の `version` を読む。スキルの基準ディレクトリ（`skills/ti-core`）から 2 つ上がプラグインの root で、そこに置かれている。**利用者に「お使いの版は何番ですか」と尋ねない。**

### 2. 公開されている最新版を取る

次の URL を取得し、`version` を読む。

```
https://raw.githubusercontent.com/tsubaiso/tsubaiso-intelligence/refs/heads/main/.claude-plugin/plugin.json
```

**`refs/heads/main` の形を使う [REQUIRED]。** `.../tsubaiso-intelligence/main/...` という短い形は**古い値を返すことがある**（2026-08-19 に実測。発行から 2 日経っても 8 つ前の版が返った）。短い形を使うと、古い版を使っている利用者に「最新です」と答えてしまう。

**取得のたびにキャッシュを避ける。** 同じ URL の結果は取得側で保持されることがあるため、末尾に毎回変わるクエリ（`?ts=` に現在時刻など）を付けて取得する。クエリの中身に意味はなく、キャッシュを外すためだけに付ける。

### 3. 比べる

`x.y.z` を数値として左から比較する。文字列として比べない（`0.9.0` と `0.12.0` の大小を取り違える）。

### 4. 結果に応じてふるまう

| 結果 | ふるまい |
|---|---|
| 自分の版 >= 公開されている版 | **何も言わない。** そのまま本題へ進む |
| 自分の版 < 公開されている版 | 本題の回答の**前に**、下記の書式で 1 行告げる。**告げたうえで本題は進める**（古いことを理由に作業を止めない） |
| 取得に失敗した・ネットワークが使えない | **何も言わずに本題へ進む。** 判定できなかったこと自体を報告しない（利用者に意味のない情報で、毎回出ると無視されるようになる） |

## 告げ方

```
お使いの Tsubaiso Intelligence は {自分の版} で、公開されている最新版は {最新版} です。
更新すると、いま無い機能が使えるようになる場合があります。管理者へ依頼してください。
```

版番号は出してよい。**プラグインの版は同梱ファイルから機械が読み取った事実**であり、利用者の記憶や申告に頼っていない。

> `capability-preflight.md` の §版で判定しない理由 は、**RobotERP ツバイソ（Salesforce パッケージ）の版**について「利用者に版を尋ねる形にすると誤案内になる」と述べたもので、本 reference とは対象が違う。あちらは判定を「その組織に現に有るか」で行い、こちらはプラグインの版を機械で読む。混同しない。

続けて何をすればよいかを聞かれたら、管理者へそのまま渡せる文面を出す。

```
Tsubaiso Intelligence の配布が最新版に追いついていません。

手元の版: {自分の版}
公開されている最新版: {最新版}

次の順で確認してください。
1. 受け皿リポジトリに追従 PR が立っていないか（立っていればマージする）
2. 追従ワークフローが動いているか（Actions のタブで最後の実行を見る）
3. 組織設定 > プラグインで「再同期」を押す／「自動的に同期」が on か確認する
```

**自分で更新しない。** 配布物を配る判断は管理者のもので、AI が代行してよい範囲を超える。手順の案内と文面の用意までにとどめる。

## 繰り返し起きるなら摩擦として起票する

同じ組織で版の遅れを繰り返し検知するなら、追従が仕組みとして機能していない。`feedback.md` の作法で摩擦として起票する。**利用者に毎回同じ案内を出し続けない。**
