# 仕様往復プロトコル（spec-roundtrip）

「カスタマイズ仕様書」を、人が追記して戻すと反映される往復にするための共通プロトコル。帳票作成・マスタインポート等のどのドメインスキルでも、設定変更の往復をこの標準スキーマと手順で回す。固有なのは「行の中身（現状仕様）」であって、往復の機構そのものは全スキル共通とする。

ドメインスキルは「現状仕様を出す／変更指示を受けて反映する」往復に入る瞬間に本書を読み、行構造・変更語彙・往復手順を本標準に合わせる。

## 標準行スキーマ（5 列・列順固定）

仕様を「安定 ID 付きの行」で表現する。列はこの 5 列・この順に固定する。

| 列 | 内容 | 制約 |
|---|---|---|
| `行ID` | 往復で不変の突合キー | 行 ID 付与規約（後述）に従う。Excel 上は保護（ロック）列 |
| `現状` | その行の現状仕様（読み取り専用・生成側が埋める） | 人は編集しない |
| `変更語彙` | 標準語彙 enum（後述の 9 値） | Excel は入力規則ドロップダウン |
| `変更指示` | 人が記入する自由欄 | — |
| `反映状態` | enum（`未反映`／`反映済`／`要相談` の 3 値） | Excel は入力規則ドロップダウン |

## 変更語彙 enum（9 値・固定）

`追加`／`削除`／`移動`／`改名`／`整形`／`条件`／`列構成`／`ブランド`／`様式` の 9 値に固定する。Excel 入力規則のドロップダウン候補にこの 9 値を載せ、自由記述は不可とする（表記ゆれ・誤りを防ぐ）。

## 行 ID 付与規約（初期値・運用調整可）

> 本節の規約は **初期値**であり、運用で調整してよい（確定済みの一次事実ではない）。

- 形式は `{スキル略号}-{3 桁連番}`（例: 帳票作成＝`RPT-001`、マスタインポート＝`MIM-001`）。スキル略号はスキルごとに固定する。
- **安定キー**: 一度発番した行 ID は往復・改版を通じて不変とする（行の意味が変わらない限り再利用する）。行を削除しても番号は再利用しない（過去往復との突合が壊れるため）。
- 機械可読正本（YAML・後述）が行 ID の真実源。Excel の `行ID` 列は正本からの転記で、人は編集しない。
- 連番桁数・略号体系はスキル数の増加に応じて運用で拡張してよい。

## 機械可読正本（YAML）と Excel の二面

機械可読の正本は YAML で内部保持し、Excel は人が触る面とする（人＝Excel／機械＝構造化の二面持ち）。YAML 1 行 ＝ Excel 1 行で、`行ID` により突合する。

```yaml
spec_roundtrip:
  skill: report-customization
  rows:
    - id: RPT-001
      current: 見積ヘッダの宛先表示位置は右上
      change_vocab: 移動         # 変更語彙 9 値のいずれか
      instruction: ""            # 人が記入（空＝変更なし）
      status: 未反映             # 未反映／反映済／要相談
```

## Excel エクスポート仕様

- 列順は上の 5 列に固定する。`変更語彙`・`反映状態` の 2 列は入力規則ドロップダウン（それぞれ 9 値／3 値）にする。
- `行ID`・`現状` の 2 列はシート保護でロックし、人は編集しない。編集可能にするのは `変更指示`・`変更語彙`・`反映状態` の 3 列のみ。
- 既定形式は `.xlsx`（非エンジニアの編集者が扱いやすい）。Markdown 表は開発者レビュー用の補助とし、顧客記入面は Excel とする。

## 往復サイクル

1. 仕様を生成し、標準行スキーマ（YAML 正本）を作る。
2. Excel へエクスポート（`行ID`・`現状` はロック、`変更語彙`・`反映状態` はドロップダウン）。
3. 人が `変更指示`（＋必要なら `変更語彙`・`反映状態`）を記入してアップロード。
4. `行ID` で現状と突合し、変更指示を反映（テンプレート／SOQL 編集等。必要ならカスタム項目追加の副フロー）。org 書込を伴う反映は `safety-gate.md` のゲートを通す。
5. 反映後に再エクスポートして次サイクルへ。YAML 正本を更新する。

## 一般化（帳票専用にしない）

同プロトコルはマスタインポート等にも同型で適用する（取込列→取込先項目のマッピングを同じ行スキーマで往復する）。ドメインごとに変わるのは「現状仕様の中身（行の意味）」だけで、5 列スキーマ・9 値の変更語彙・行 ID 突合の機構は共通とする。
