# 成果物の版の作法（deliverable-versioning）

TI が出す成果物（設計書・仕様書・帳票テンプレ・項目マッピング・移行手順・回答書）を、指示を受けて直すときの版の扱い。どの局面スキルでも同じ型になるため本基盤に置き、各スキルは本 reference を指すだけにする。

## いつ読むか

- 一度提示した成果物を、指示を受けて直そうとした瞬間
- 仕様往復（`spec-roundtrip.md`）で設計書・仕様書を出し直す瞬間

## 守ること

1. **提示した版は上書きしない [REQUIRED]。** 直すときは次の版（`_v{N+1}`）を新しく作る。提示前の起草中は同じ版を直してよい。判定は「この修正の前に、一度でも相手に見せたか」の一点。
2. **各版は単体で完結する [REQUIRED]。** 「前版のとおり」「変更点のみ」で中身を省かない。最新版だけを渡された人が、それだけで読めること。
3. **差分を追えるようにする。** 末尾に簡潔な変更履歴を置き、何を変えたかを版ごとに 1 行で残す。
4. **版の番号の付け方・置き場・命名は利用者の作法に従う。** 本作法が求めるのは上の 3 点だけで、フォルダ構成やファイル名の型には踏み込まない。

## なぜ

上書きすると、承認・レビューを通した版が消え、指示のどれが反映されたかを辿れなくなる。前版参照で省くと、最新版だけを受け取った人が読めない。往復が長くなるほど、この 2 つは静かに効く。
