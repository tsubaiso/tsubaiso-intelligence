# フィードバック／ナレッジギャップ（feedback）

各ドメインスキルでユーザーがつまずく／やり取りが多発する、あるいは知識検索で答えに辿り着くのに回り道する——こうした摩擦を「フィードバックイベント」として捉え、Tsubaiso 側へ送って蓄積する共通機構。蓄積されたイベントは人がレビューし、スキル改善またはカスタムナレッジ追加に繋げる。

ドメインスキルは、ユーザーが繰り返し詰まる／失敗する摩擦を検知した瞬間に本書を読み、匿名化済みのシグナルをフィードバックイベントとして渡す。

> **P1 の挙動**: 送信 IF `tsubaiso_feedback.submit` は **P1 ではローカルスタブ（記録のみ・実送信しない）**。オプトインは既定 OFF。実送信・蓄積・トリアージ・配信は Tsubaiso Feedback MCP 立上げ後（P2）に行う。P1 はスキーマと発火点を固めておき、立上げ時にスタブを実送信へ差し替えるだけで全ドメインスキルに一斉に効く状態にする。

## イベント JSON スキーマ（7 キー）

イベントは次の 7 キーで構造化する。

```json
{
  "skill_name": "report-customization",
  "skill_version": "v7",
  "event_type": "skill_friction",
  "context": {
    "step_id": "spec-roundtrip.apply",
    "trajectory": ["...匿名化した操作軌跡..."],
    "stuck_step": "反復調整ループが収束しない"
  },
  "classification": "loop_non_convergence",
  "resolution_candidate": "SKILL 改善候補 or カスタムナレッジ候補",
  "dedup_key": "再現キー（生成規則は後述）"
}
```

- `event_type` は **2 値固定**。`skill_friction`（該当スキルの SKILL.md 改善へ）／`knowledge_gap`（ナレッジ追加へ）のいずれか。
- `context` には**業務データ本体を入れない**。操作軌跡・詰まったステップなどのテレメトリのみとし、PII マスキングを必須とする（名前・金額・取引内容等の業務データは送らない）。

## 2 系統のイベント

| 系統（`event_type`） | 何を捉えるか | 反映先 |
|---|---|---|
| `skill_friction` | どのスキルのどのステップで詰まったか | 該当スキル（SKILL.md）の手順・型・落とし穴を改善 |
| `knowledge_gap` | 知識検索で答えが出ない／回り道した | カスタムナレッジを追加し、次回から最初に提示 |

## dedup_key（再現キー）生成規則（初期値・運用調整可）

> 本節の規約は **初期値**であり、試験運用後にチューニングしてよい（確定済みの一次事実ではない）。

- `dedup_key ＝ hash(skill_name ＋ step_id ＋ 正規化した詰まり意図)`。同一の詰まりセッションを 1 イベントに集約する（送信過多を防ぐ＝「1 つの詰まり＝1 イベント」）。
- 正規化は言い直し・語順差を吸収し、同義の往復を同一キーへ寄せる。
- ハッシュ対象・正規化の粒度は運用で調整する。

## 発火点と P1 挙動

- ドメインスキルは、反復調整ループが収束しない／カスタム項目追加が失敗する／取込で源が見つからず空欄が多発する等の摩擦を検知した瞬間に、本イベントを生成して渡す。
- **P1 の発火**: しきい値による自動判定は行わない。ドメインスキルが「ユーザーが繰り返し詰まる／失敗する」と判断した時点で 1 件記録する（1 つの詰まり＝1 イベント＝同一 `dedup_key` で集約する）。
- **しきい値運用は P2**: 往復回数・所要ターン等のしきい値に基づく自動送信は、実送信段階（P2・Tsubaiso Feedback MCP 立上げ後）で適用する。P1 はローカルスタブで記録するのみのため、本書はしきい値の具体値を持たない。
- P1 はオプトイン既定 OFF。送信内容は ON でも常にテレメトリのみ（業務データ本体なし）。
