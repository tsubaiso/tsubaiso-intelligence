# ti-selfcheck — TIの接続とスキルを点検する

利用者が「TIは正しく組み上がっているか」を知りたいときの入口。**接続とスキルを1つずつ確かめ、何が ○ で何が × かを表で返す。** × には、考えられる原因と、次に何をすればよいかを添える。

**本スキルはSKILL.md 1ファイルで完結する [REQUIRED]。** 参照用のフォルダを持たず、ほかのスキル（ti-coreを含む）も前提にしない。点検の対象は「スキルが欠けている」「接続が無い」状態そのものなので、点検する側が同じ壊れ方をすると点検が動かない。**本スキルに参照用のフォルダを足さない。**

## 守ること [REQUIRED]

1. **結果を作らない。** 呼べなかった・読めなかった・判定できなかった項目は「未確認」と書く。○ にも × にもしない
2. **見えるものだけで判定する。** 判定に使うのは「ツールがあるか」「呼んで応答が返るか」「ファイルがあるか」の3つだけ。AIクライアントの設定画面は見えないので、画面の状態は「〜と考えられます」で書き、断定しない
3. **業務データに触れない。** 点検のために呼ぶのは §点検の項目 に書いた呼び出しだけ。組織のレコードを読む・集計する呼び出しをしない
4. **途中で止めない。** 前の項目が × でも、最後の項目まで確かめてから表にまとめる。1か所ずつ利用者と往復させない
5. **利用者に版や設定を尋ねない。** 機械で読めるものは読む。尋ねてよいのは、AIクライアントの種類が推定できないときだけ
6. **点検だけを行う。** 設定を直す操作は本スキルでは行わない。直すのはAIクライアントの画面での人の操作か、ti-rollout

## 点検の項目

上から順に確かめる。

| # | 項目 | 確かめ方 | ○ の条件 |
|---|---|---|---|
| 1 | 基盤のスキル | 読み込めるスキルの中に `ti-core` があるか | `ti-core` がある |
| 2 | スキルの中身 | §スキルの中身の確かめ方 のとおり | 欠けているファイルが無い |
| 3 | スキルの版 | §スキルの版の確かめ方 のとおり | 手元の版 >= 公開されている最新版 |
| 4 | ナレッジの接続 | 名前が `isoppy_search` で**終わる**ツールがあるか。あれば「Tsubaiso Intelligence」を検索語に1回呼ぶ | ツールがあり、エラーでない応答が返る（0件でも ○） |
| 5 | アトラスの接続 | 名前が `atlas_domain_index` で**終わる**ツールがあるか。あれば1回呼ぶ | ツールがあり、業務領域の一覧が返る |
| 6 | ツバイソPSAの接続 | §ツバイソPSAの接続の確かめ方 のとおり | 下記のいずれかの型のツールがあり、エラーでない応答が返る |

**ツール名は末尾で照合する [REQUIRED]。** AIクライアントによって前置きが付く（例: `mcp__…__isoppy_search`）ため、完全一致で探すと、あるものを「無い」と判定する。

**同じ末尾のツールが複数あるときは、すべて列挙して1本ずつ判定する [REQUIRED]。** 本番とサンドボックスを並べて接続している場合や、TI以外のSalesforceの接続がある場合がある。どれか1本が ○ でも、ほかが × なら行を分けて示す。

### スキルの中身の確かめ方

1. **スキルのフォルダの中身を一覧できるかを先に確かめる。** 一覧できない環境では、項目2は「未確認」とする。ファイルを開く道具が無いことと、ファイルが無いことを混同しない
2. 名前が `ti-` で始まる各スキル（本スキルを除く）のSKILL.mdを開き、本文に書かれた `references/` で始まるパスを拾う
3. **そのスキル自身のファイルでないものを除く。** 同じ文の中にほかのスキル名（`ti-core` など）が出てくるものは、そのスキルのファイルなので、そちらのスキルの側で確かめる。`skills/…/` から始まるパスは、パスが示すスキルの側で確かめる
4. 残ったパスについて、スキルのフォルダの一覧にそのファイルがあるかを見る。**一覧にあって開けないものは「未確認」、一覧に無いものが × の根拠**

期待するファイルの一覧を本スキルに持たない。各スキルのSKILL.mdに書かれたパスを手がかりにする。一覧を書き写すと、各スキルの改訂に追従できず、本スキルが古くなる。

### スキルの版の確かめ方

**プラグインの版とスキルの版は別の系列で、混ぜて比べない [REQUIRED]。** プラグインの版は配布物全体の版（`0.34.0` の形）、スキルの版は各SKILL.mdの先頭に書かれた `version`（`ti-core` なら `0.14.0` の形）。

1. **プラグインの版で比べられるとき。** 本スキルの基準ディレクトリから2つ上に `.claude-plugin/plugin.json` があれば、その `version` を手元の版とする。公開されている最新版は次の2つから取り、**大きいほう**を採る。片方だけ取れたときはその値を使う
   - `https://github.com/tsubaiso/tsubaiso-intelligence/tags.atom` の各エントリの `<title>`（`v0.34.0` の形）から先頭の `v` を外し、**全件の最大値**を採る。並び順に頼らない
   - `https://raw.githubusercontent.com/tsubaiso/tsubaiso-intelligence/refs/heads/main/.claude-plugin/plugin.json` の `version`
2. **`plugin.json` が無く、本スキルの版の刻印があるとき**（スキルを1つずつアップロードする環境など）。本SKILL.mdの見出しの上にある `<!-- plugin-version: X.Y.Z -->` の行の `X.Y.Z` を手元の版とし、1と同じ2つから取った最新版と比べる。この行は配布物を発行するときに、そのときのプラグインの版で書き込まれる（frontmatterのキーにしないのは、共通仕様に無いキーを足さないため）。**`X.Y.Z` が数字3つの形でない行（発行前の `unreleased` など）は刻印が無いものとして扱い、3へ進む**
3. **`plugin.json` も刻印も無いとき**（刻印を始める前に配布されたスキル）。`ti-core` のSKILL.mdの `version` を手元の版とし、`https://raw.githubusercontent.com/tsubaiso/tsubaiso-intelligence/refs/heads/main/skills/ti-core/SKILL.md` の先頭の `version` と比べる。結果の表には「ti-coreの版で比べた」と書き添える
4. `x.y.z` を左から数値として比べる。文字列として比べない（`0.9.0` と `0.12.0` の大小を取り違える）
5. 最新版を取得できないとき、または外部URLの取得に利用者の許可確認が要る環境では、**許可を求めずに**項目3を「未確認」とする

### ツバイソPSAの接続の確かめ方

ツバイソPSAの接続には2つの型がある。どちらかの型のツールがあれば、その型で判定する。

| 型 | 見分け方（ツール名の末尾） | 呼び出し |
|---|---|---|
| 標準の構成 | `discover` と `dispatch_readonly` がそろっている | `discover` を「company profile」を検索語に1回呼ぶ |
| 参照・更新に絞った構成 | `getUserInfo` がある | `getUserInfo` を1回呼び、接続中のユーザー名を結果の表に書く。**接続先の組織はユーザー名で示す**（Salesforce のユーザー名は全組織を通じて一意）。会社名の欄が返っても組織名とは限らないので、組織名として書かない |

- どちらの型のツールも無ければ「未設定」とする（× にしない。導入の途中では、まだ設定していないことがある）
- ツールがあって呼んだが、エラーが返ったときは × とする
- **標準の構成の点検では、どの組織につながっているかまでは確かめない。** 結果の表にそう書き添える

### 結果の分け方

| 結果 | 使うとき |
|---|---|
| ○ | ○ の条件を満たした |
| × | ツールやファイルが無い、または呼んだが失敗した |
| 未設定 | 項目6で、どちらの型のツールも無いとき |
| 未確認 | 呼べなかった・読めなかった・取得に失敗した・判定の手段が無い |

## 考えられる原因と次の一手

× と未設定の行には、考えられる原因と次の一手を書く。代表的な型は次のとおり。

| 項目 | 症状 | 考えられる原因 | 次の一手 |
|---|---|---|---|
| 1 | `ti-core` が無い | 基盤のスキルが追加されていない | セットアップ手順の作業2（組織へまとめて配布している場合は作業4） |
| 2 | ファイルが欠けている | スキルを追加するときに、スキルのフォルダの一部が含まれなかった | セットアップ手順の作業2で、そのスキルを作り直して置き換える（組織へまとめて配布している場合は作業4） |
| 3 | 手元の版が古い | 配布が止まっている、またはアップロードしたスキルを置き換えていない | 管理者へ依頼する |
| 4・5 | ツールが無い | そのコネクタが追加されていない、接続が作成されていない、または**追加・接続より前から開いていたチャットで点検している**（使えるツールがチャットを開いた時点で決まるクライアントがある） | 新しいチャットを開いて点検し直す。それでも無ければセットアップ手順の作業3 |
| 4・5 | 呼んだら認証のエラー | 接続のサインインが切れている、または完了していない | 接続を作り直して、サインインをやり直す |
| 5 | 呼んだら403（Forbidden） | ツバイソの契約の判定で拒否された | ツバイソへ連絡する（下記 §ツバイソへ送れる形） |
| 4〜6 | 呼んだが上記以外のエラー | 判別できない | エラーの原文を表の下に添え、ツバイソへ連絡する |
| 6 | 未設定 | ツバイソPSAへの接続が設定されていない | セットアップ手順の作業5 |

**画面の操作手順を本スキルに書き写さない [REQUIRED]。** 次の一手では、利用者のAIクライアントのセットアップ手順（下表）の**どの作業を開けばよいか**を、記事のURLとあわせて示す。手順の記事が改訂されても、本スキルが古い手順を案内しないようにするため。作業の番号は、どのAIクライアントの記事でも共通。

| AIクライアント | セットアップ手順 |
|---|---|
| 共通（本体） | https://support.tsubaiso.jp/hc/ja/articles/62236593830681 |
| Claude | https://support.tsubaiso.jp/hc/ja/articles/62322858312217 |
| Cursor | https://support.tsubaiso.jp/hc/ja/articles/62322866159385 |
| ChatGPT | https://support.tsubaiso.jp/hc/ja/articles/62322851746585 |
| Microsoft Copilot Studio | https://support.tsubaiso.jp/hc/ja/articles/62322851798169 |

上の記事は、ツバイソのヘルプセンターにサインインした状態で開ける。サインインしていないと開けないので、利用者が記事を開けないと伝えたらサインインを案内する。

利用者のAIクライアントは、ツール名の前置きの形や会話の手がかりから推定する。推定できなければ尋ねる。

## 返し方

次の形で返す。表の前に前置きを書かない。**利用者向けの言葉で書く。** ツール名・プロトコル名・ファイルのパスは表に出さず、必要なら表の下に「詳細」としてまとめる。

```
Tsubaiso Intelligenceの点検結果（{日時}）

| 項目 | 結果 | 考えられる原因 | 次の一手 |
|---|---|---|---|
| 基盤のスキル | ○ | | |
| スキルの中身 | × | ti-coreの一部のファイルが見つかりません。スキルを追加するときに、フォルダの一部が含まれなかったと考えられます | 手順の作業2で、ti-coreを作り直して置き換えてください（{記事のURL}） |
| スキルの版 | 未確認 | 最新版の情報を取得できませんでした | |
| ナレッジの接続 | ○ | | |
| アトラスの接続 | × | アトラスのツールがありません。コネクタの接続が作成されていないと考えられます | 手順の作業3（{記事のURL}） |
| ツバイソPSAの接続 | 未設定 | ツバイソPSAへの接続がありません | 手順の作業5（{記事のURL}） |

6項目のうち、○ が2、× が2、未設定が1、未確認が1です。× の項目を直したあと、もう一度「TIの状態を点検して」と入力してください。
```

- **項目1・2・4・5・6がすべて ○ のとき**は、最後の文を「接続とスキルがそろっています。drift check（意味定義と組織の構造のずれの確認）へ進めます。」にする。項目3が未確認でも進めてよい
- **項目5または6が ○ でないとき**、drift checkには進めないと書き添える。drift checkはアトラスとツバイソPSAの両方を使うため
- 表の原因・次の一手は1〜2文に収める。長い説明は表の下へ回す

### ツバイソへ送れる形

表の下に、次の1行を添える。利用者が結果をツバイソへ送ったとき、ツバイソ側で読み解き直す往復をなくすため。

```
この結果は、そのままツバイソへお送りいただけます（環境: {AIクライアント}／{日時}／版 {手元の版 または 未確認}）
```

## drift checkを頼まれたとき

drift check（`atlas_drift_check`）を頼まれて、項目5または6のツールが無いときは、「実行できません」で終えない。**本スキルの点検に切り替えて、何が欠けているかを表で返す。** 欠けているものがそろえばdrift checkを実行できる、と書き添える。

## 直したあと

直すのは本スキルの役割ではない（守ること6）。接続を作り直す・スキルを置き換えるなどの作業は、AIクライアントの画面で人が行うか、ti-rolloutで行う。**直したあとは、本スキルをもう一度最初から実行して確かめる。**
