# 拡張アプリの導入・版上げ・設定変更・アンインストール（extension-apps）

> **ベータとして先行提供している機能です。** 記述が変わることがあります。扱いは ti-core の `references/beta-status.md` を参照してください。本 reference が扱う拡張アプリの導入・版上げ・設定変更・アンインストールはベータで、差分方式のメタデータ設定は正式提供です。

**拡張アプリ**は、ツバイソ株式会社が PSA/IMA に足す機能として無料で提供するアンロックドパッケージである。依頼者（管理者）は拡張アプリの一覧から必要なものを選び、TI への指示で導入・版上げ（アップグレード）・設定変更・アンインストールまで行う。本書はその手順を、**どの拡張アプリにも共通する形で**持つ。

本書では、TI に指示する人を**依頼者（管理者）**、権限セットを割り当てて拡張アプリを使う Salesforce のユーザーを**使う人**と呼ぶ。

## いつ読むか

- 依頼者が拡張アプリの導入・版上げ・設定変更・アンインストールを依頼したとき
- 依頼者が拡張アプリの名前を挙げて、使えるか・何ができるかを訊いたとき（可否と操作はナレッジで答え、導入へ進むときに本書へ戻る）
- PSA/IMA を版上げした組織に、拡張アプリが導入済みのとき（§版上げ）

## 拡張アプリごとの値は本書に書かない [REQUIRED]

拡張アプリの一覧と、拡張アプリごとに決まる値は、**ナレッジ**にある。一覧の記事から各拡張アプリの記事へ降りて引く（引き方は ti-core `references/knowledge-lookup.md`）。本書には書かず、作業のたびに引く。拡張アプリが増えても本書は変わらない。

| 引く値 | 使う手順 |
|---|---|
| パッケージのバージョンID（`04t` で始まる）と版番号。昇格済み（released）の版に限る（アンロックドパッケージは、昇格していない版を本番組織に入れられない） | §導入 手順3・§版上げ |
| 名前空間（あれば）。当社の名前空間として扱う | 拡張アプリのオブジェクトのレコードを作成・更新するとき（ti-reference `references/write-index.md` §他社のパッケージのオブジェクトへは書かない で、当社のものとして見分ける） |
| 対応する PSA/IMA の版 | §導入 手順1・§版上げ |
| 拡張アプリが手を入れるオブジェクトと、外部の接続先（あれば） | §導入 手順1・§承認と確認 |
| 権限セットと、割り当てる使う人の範囲 | §導入 手順4 |
| 既定の設定（カスタムメタデータのレコード）と、版ごとに増えた設定 | §導入 手順5・§版上げ |
| 依頼者が変更できる設定の範囲と値 | §設定変更 |
| 導入後の確認の観点 | §導入 手順6 |

**ナレッジに値が無いときは、推測で埋めずに止める [REQUIRED]。** バージョンIDや既定の設定を、組織の現状・過去の会話・別の拡張アプリから補わない。未解決として ti-core `references/support-escalation.md` の導線でサポートへ引き継ぐ。

拡張アプリの既定の設定は、パッケージに含めずに導入時に配備する。パッケージに含めると、版上げのたびに依頼者が変えた設定がパッケージの値で上書きされるためである。そのため、導入は「パッケージのインストール」と「既定の設定の配備」の2段になる。本書は、既定の設定の型（カスタムメタデータ型・`__mdt`）はパッケージに含め、そのレコードはパッケージに含めない、という作りを前提にする。

## 承認と確認 [REQUIRED]

パッケージのインストールには、メタデータの checkonly に当たる事前の検証が無い。**検証組織で同じ手順を先に通すことを、その代わりにする。**

- **検証組織が無いときは導入しない。** PSA/IMA を入れた検証組織（トライアル組織・sandbox）が無いことを依頼者へ伝え、本番組織へ直接入れない。
- **本番組織かどうかは、別名（alias）だけで決めない。** 次の照会の結果で判定し、依頼者にも確かめる。トライアル組織は `IsSandbox` が false を返すので、`IsSandbox` だけで判定しない。
  ```sql
  SELECT IsSandbox, OrganizationType, TrialExpirationDate FROM Organization
  ```
  `IsSandbox` が true なら sandbox、`TrialExpirationDate` に値が入っていればトライアル組織で、どちらも検証組織として扱う。どちらでもなければ本番組織として扱う。`OrganizationType`（組織の種類）は判定には使わず、依頼者へ確かめるときに判定の結果と並べて示す。
- **本番組織では、手順3〜5をまとめて1回の承認を得てから実行する**（SKILL.md §安全弁3）。承認の提示には、拡張アプリ名・版・入れる組織・割り当てる権限セットと使う人・配備する既定の設定・外部の接続先・拡張アプリが手を入れるオブジェクトにある既存のトリガと入力規則（§導入 手順1）を並べる。版上げでは「版上げは元の版へ戻せない」ことを、アンインストールでは消えるものと「元に戻せない」ことを添える。
- **検証組織でも、実行の前に依頼者の確認を取る**（SKILL.md §org カテゴリと安全弁 の保護カテゴリ）。

## 導入

1. **前提を確かめる。** 導入済みのパッケージと版を取る。その拡張アプリが導入済みなら §版上げ へ進む。未導入なら、ナレッジの「対応する PSA/IMA の版」と照らし、満たさないときは導入せず、先に PSA/IMA の版上げが要ることを伝える。あわせて、拡張アプリが手を入れるオブジェクトにある既存のトリガ・入力規則・Flow を、SKILL.md §カスタマイズ着手プリフライト の軸2の方法で列挙する。
   ```bash
   sf package installed list --target-org <org> --json
   ```
2. **入れる組織と使う人を依頼者に確認する。** 使う人は依頼者が決める。AI が組織のユーザー一覧から推定して割り当てない。
3. **パッケージをインストールする。** `--json` の結果で成否を判定する。待ち時間を過ぎて処理中が返ったときは再実行しない。返ったインストール要求の ID（`0Hf` で始まる）で状態を確かめる。
   ```bash
   sf package install --package <04t…> --target-org <org> --wait 30 --security-type AdminsOnly --upgrade-type DeprecateOnly --no-prompt --json
   sf package install report --request-id <0Hf…> --target-org <org> --json
   ```
   `--no-prompt` は、外部の接続先（リモートサイト設定・CSP の信頼済みサイト）を確認なしで登録する。外部の接続先は、§承認と確認 の提示に載せて承認を得たものに限る。
4. **権限セットを割り当てる。** ナレッジの権限セットを、手順2で確認した使う人へ割り当てる。
   ```bash
   sf org assign permset --name <権限セット> --on-behalf-of <ログインに使うユーザー名> --target-org <org> --json
   ```
5. **既定の設定を配備する。** ナレッジの既定の設定（カスタムメタデータのレコード）を、SKILL.md §中核ループ（差分方式）で配備する（対象メタデータの表の14）。カスタムメタデータのレコードの配備は、プリフライトでは低リスクとして扱う。組織に同じ名前のレコードが既にあるときは上書きしない。retrieve して差分を依頼者へ示し、どちらを残すかを確認する。
6. **確かめる。** 照会で、導入された版・権限セットの割り当て・既定の設定のレコードを確かめる。ナレッジの「導入後の確認の観点」に画面の確認があれば、使う人に開いてもらう（AI は使う人としてログインできない）。
7. **記録する。** SKILL.md §中核ループ 手順7の設計書に、拡張アプリ名・版・配備した既定の設定を記載する。既定の設定のレコードはパッケージの外にあり、組織では購読側のカスタマイズとして見えるため、出所を設計書で辿れるようにする。

## 版上げ

拡張アプリの新しい版が出たとき、または PSA/IMA を版上げしたときに通す。**版上げは元の版へ戻せない**ので、§承認と確認 を必ず通す。

1. 導入済みの版を `sf package installed list` で取り、ナレッジの最新の版・対応する PSA/IMA の版と照らす。
2. 検証組織で、新しい版のバージョンIDを指定して §導入 手順3 のコマンドを実行する。`--upgrade-type` は `DeprecateOnly`（版で外されたコンポーネントを削除せず、非推奨にするだけ）とする。**ナレッジが `DeprecateOnly` 以外を指定しているときは、削除されるコンポーネントとデータが消えることを承認の提示に載せる。** 本番組織では `Delete` を使わない。
3. **導入済みの版から増えた設定だけを足す。** どの設定が増えたかは、ナレッジの版ごとの差分から引く。組織に無いレコードを一律に足さない（依頼者が意図して消したレコードを戻さないため）。既存の設定に項目が増えたときの扱いも、ナレッジに従う。**依頼者が変えた既存のレコードを既定の値へ戻さない [REQUIRED]。**
4. 検証組織で §導入 手順6 を通してから、承認を得て本番組織へ同じ手順を通し、§導入 手順7 の設計書に新しい版を記載する。

## 設定変更

1. ナレッジで、依頼者が変更できる設定の範囲と値を引く。範囲の外にある変更は行わず、範囲の外であることを依頼者へ伝える。
2. 対象のレコードを retrieve し、変更前と変更後の値を依頼者へ示す。
3. SKILL.md §中核ループ（差分方式）で配備し、手順7で設計書を出力する。

## アンインストール

**アンインストールは元に戻せない。** 拡張アプリのコンポーネントと、そのデータが消える。§承認と確認 を必ず通す。**検証組織が無いとき、または検証組織に本番組織と同じ版が入っていないときは、アンインストールしない。**

1. **消えるものと残るものを並べる。** ナレッジで、アンインストールで消えるもの（拡張アプリのオブジェクトとそのデータ・拡張アプリが標準オブジェクトに足した項目とその値・タブ・権限セット・既定の設定の型とレコード）と、消えずに残るものを引く。ナレッジに無いときは止める（§拡張アプリごとの値は本書に書かない）。あわせて、拡張アプリのオブジェクトに依頼者の組織で足した項目・入力規則・ボタンなどを、本番組織と検証組織のそれぞれから一覧にする。これらはアンインストールを止めず、オブジェクトと一緒に消える。
2. **入っている版を組織ごとに取る。** `sf package installed list --target-org <org>` で、その組織に入っている版のバージョンID（`04t` で始まる）を取る。ナレッジの最新の版のIDを使わない。本番組織と検証組織のIDが一致しないときは止める。組織が本番組織か検証組織かは、§承認と確認 の方法で確かめる。
3. **検証組織で先にアンインストールする。** 時間切れで処理中が返ったときは再実行しない。返った要求の ID（`06y` で始まる）で結果を確かめる。
   ```bash
   sf package uninstall --package <04t…> --target-org <org> --wait 30 --json
   sf package uninstall report --request-id <06y…> --target-org <org> --json
   ```
   依頼者の組織で作ったカスタマイズ（レポート・FlexiPage・Flow など）や、ほかのパッケージが拡張アプリのコンポーネントを参照していると、アンインストールは失敗する。失敗しても何も消えない。参照しているものの一覧を依頼者へ示す。ほかのパッケージが参照しているときは、そこで止める。依頼者の組織のカスタマイズの参照を外すのは、別のカスタマイズの変更として SKILL.md §中核ループ（差分方式）と §承認と確認 を通す。既定の設定のレコードがアンインストールを止めたときは、レコードを retrieve して残してから削除し、アンインストールをやり直す。
4. **本番組織の直前に残す。** 本番組織で実行する直前に、消えるデータを依頼者がエクスポートしたこと、手順1で一覧にしたカスタマイズと既定の設定のレコードを本番組織から retrieve して残したことを確かめる。依頼者がエクスポートしないと決めたときは、そのデータが消えることを承認の一覧に含める。
5. **本番組織で参照を外す。** 手順3で外した参照があれば、本番組織でも同じ変更を、別の承認を得て先に済ませる。既定の設定のレコードを先に削除する必要があったときも、ここで済ませる。
6. **本番組織で実行する。** 承認の一覧に、手順1で消えるもの・手順5で済ませた変更・手順7で手で削除するものを並べ、「元に戻せない」ことを添えて1回の承認を得る。承認を得てから、手順3のコマンドを本番組織に対して実行する。本番組織だけで失敗したとき（検証組織に無い参照があったとき）は、手順5に戻り、承認を取り直す。
7. **残ったものを片づける。** 手順1で残るとしたものがあれば、ナレッジに従って手で削除する。§導入 手順7 の設計書に、拡張アプリをアンインストールしたことを記載する。

## 本書に書かないこと

- 拡張アプリごとの値（§拡張アプリごとの値は本書に書かない）
- 拡張アプリの機能の使い方と可否。ナレッジにあり、ti-howto が引いて答える
- 拡張アプリが加える業務の操作。業務の操作を扱う既存のスキルの手順に従う
- **元の版への戻し。** アンロックドパッケージは古い版へ戻せない。依頼されたときは、ti-core `references/support-escalation.md` の導線でサポートへ引き継ぐ
