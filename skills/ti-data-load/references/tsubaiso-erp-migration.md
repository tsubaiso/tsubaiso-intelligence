# ツバイソERPへ移行のデータを入れる（ERPのMCP）

本書の「ツバイソERP」は会計の製品を指す（定義はti-reference `references/tsubaiso-erp-web-api.md`）。本スキルの他のreferenceが扱うPSA/IMAの組織への投入とは別の製品で、PSA/IMAの書込前ゲート（`atlas_write_seam`）・外部IDによる関係解決・自動作成シームはツバイソERPには掛からない。本書が持つのは、ツバイソERPを使い始めるときに、移行元の資料からマスタ・期首の残高・固定資産を入れる手順である。日常の振替伝票と、資料からの販売・購買の伝票の登録はti-update `references/tsubaiso-erp-write.md` が持つ。

## いつ読むか

- ツバイソERPへの移行（使い始めるときのデータの投入）を頼まれた瞬間（移行元の資料を読み始める前）
- 移行の途中で `call_web_api` が200番台以外を返した瞬間、または応答が200番台でも送った件数と読み戻した件数が合わない瞬間（§途中で止まったとき・失敗したとき）
- 移行の途中で接続をつなぎ直した瞬間（条件3をやり直す）

先にti-reference `references/tsubaiso-erp-web-api.md` を読み、Atlasで呼び方を引ける状態にしておく。Atlasを引けないときは移行を始めない。

## 対象と範囲

| 対象 | この手順で行うこと |
|---|---|
| 事業年度 | 読むだけ（状態・期首・利用開始日）。作成と、状態の切り替えは利用者が画面で行う |
| 部門・勘定科目（補助科目を含む）・セグメント・銀行口座・売掛金と買掛金の管理区分・取引先 | 既存と突き合わせ、無いものだけを1件ずつ作る |
| 期首残高（部門ごとの勘定科目）・取引先別の開始残高・銀行口座の期首残高 | 置き換えで入れる（§期首の残高は置き換えで入れる） |
| 固定資産 | 取得の仕訳を作らずに1件ずつ作り、償却の予定まで作る（§固定資産） |
| 期中に使い始めるときの、期首から利用開始日の前の月までの月ごとの合計 | 振替伝票で入れる（§期中に使い始めるとき） |

**この手順で行わないもの。** 取引の明細（売掛・買掛の伝票・経費精算・給与など。期首の残高と月ごとの合計で引き継ぐ）／社員（ログインできるアカウントの作成を伴うため。画面の取込を案内する）／資産種類の作成（既定の資産種類に移行元の種類を当てる。足りなければ画面で作るよう案内する）／作ったマスタ・固定資産の削除（画面で行うよう案内する。§この手順で作った取引先・銀行口座は画面で直せる人が限られる）。

**一括で作る呼び方は、Atlasに無いあいだは使わない。** いまマスタと固定資産を作る呼び方は1件ずつで、画面にある一括の取込はファイルを送るためERPのMCPから使えない。件数が多いと時間がかかり、途中で接続のつなぎ直しが起きる（条件3）。一括の呼び方が加わったら、Atlasの `呼び方:` に現れる。推測で組み立てない。

## POSTしてよい条件 [REQUIRED]

**次の6つをすべて満たすまでPOSTしない。**

1. **利用者が移行を明示して頼んでいる。** 参照・集計の依頼の途中で、AIの判断で投入へ進まない
2. **Atlasの `呼び方: POST …` の文に挙がり、移行で使うと書かれたpathだけを使う。** `呼び方:` に無いpath（画面の取込・既存を上書きする登録・前期末の残高から期首残高を計算して返す口・削除・アカウントの作成）は使わない。例外は期中の月ごとの合計の振替伝票で、ti-update `references/tsubaiso-erp-write.md §POSTしてよい条件` の2で判定する（§期中に使い始めるとき）。GETも、意味定義が読み方に挙げる呼び方だけを使い、読むと記録を作る呼び方は §読むと記録を作る呼び方 の線を守る
3. **書き込み先の法人を確かめている。** 1つの接続は1つの法人に結びつき、有効期限は最長1時間で、つなぎ直すときに利用者が法人を選び直す。検証用の法人と本番の法人を取り違えると、エラーにならずに別の法人へ入る。法人名の扱いはti-update `references/tsubaiso-erp-write.md §POSTしてよい条件` の3と同じで、読めないときは「書き込み先の法人名は未確認」と書き、接続のときにどの法人を選んだかを利用者に確かめる。**401のあと・つなぎ直したあとは、次のPOSTの前にこの条件をやり直し、次の2つを読み直して照らす。** (a) 段2で読んだ事業年度の期首・利用開始日と、部門・取引先の件数（段3で読んだ件数に、この手順で作った件数を足したもの） (b) 段5で控えた対応表のうち1件を、1件を取得する呼び方で読み、移行元のコードと合うか。検証用の法人は本番に合わせて用意するため、(a) だけでは見分けられないことがある。どちらかが食い違ったら別の法人とみなして止める
4. **対象の種類ごとに投入計画を示し、承認を得ている**（§承認の単位）
5. **送る前の検査を通している。** 各対象の意味定義の `rule` が挙げる必須の項目・送る前に確かめること・拒まずに飛ばされるものを、送る前にAIの側で確かめる。ツバイソERPは、無い勘定科目のコード・期首に開設されていない口座などを、エラーにせず飛ばして200を返すことがある
6. **送ったあとは `GET` で読み戻し、移行元と突き合わせる**（§答え合わせ）。応答の本文だけで「入った」と報告しない

## 承認の単位

ti-update `references/tsubaiso-erp-write.md` は1件ずつ承認を得る。**移行ではこれを、本スキルの投入計画の承認（SKILL.mdの発火点表「orgへデータを書き込む直前」）に置き換え、対象の種類ごとに1回承認を得る。** 移行の担当者が数百件を1件ずつ承認する形は成り立たないためで、内容を示して承認を得ることは変えない。

| 対象 | 投入計画に示すもの |
|---|---|
| マスタ・固定資産 | 作る件数・代表の数件・既存と重複するため作らないもの・移行元のコードとの対応表・省いたときに既定の部門が入る項目・指定できず区分や種類で決まる項目（取引先の売掛金・買掛金の科目は管理区分で、銀行口座の科目は口座の種類で決まる）。取引先・銀行口座を作るときは、作ったものを画面で直せる・消せるのは管理者などの権限を持つ人に限られること |
| 期首残高 | 部門ごとに、いまの値と送る値（送る全科目と金額）・送ると消える明細。借方と貸方の合計。部門管理を使うときは、全部門の合計の一致も示す（製品は部門ごとの一致を見ないため） |
| 取引先別の開始残高 | 科目ごとに、送る全取引先と金額・開始残高を消す取引先。合計と、突き合わせる相手（§答え合わせ） |
| 銀行口座の期首残高 | 送る全口座と金額 |
| 期中の月ごとの合計 | 月ごとの全科目と金額 |

いずれにも、書き込み先の法人名（条件3）と、送る前の検査の結果を添える。承認とみなすのは、示した計画に対する返答だけにする。示していない種類まで含めて以後を任せる形の承認は受けない。**計画は、前の種類を送って読み戻したあとの値で組む**（§手順の段4）。承認したあとで計画の値が変わったら、示し直して承認を得る。

## 手順

| 段 | すること |
|---|---|
| 1 | 書き込み先の法人を確かめる（条件3）。検証用の法人で流すのか本番の法人で流すのかを、利用者と言葉で確かめる。**本番の法人なら、検証用の法人で同じ手順を流して答え合わせを済ませたかを確かめ、済んでいなければ本番の法人へは進まず、まず検証用の法人で段1〜7を流す**（§検証用の法人で先に流す） |
| 2 | 前提を確定する。事業年度の一覧を読み、対象の期の状態・期首・利用開始日を確かめる。状態が導入中でなければ投入を始めず、画面で期を用意するよう利用者へ伝える。利用開始日が期首の月と違えば期中に使い始めるものとして扱い、§期中に使い始めるとき の確かめることを利用者と決める。部門管理を使うかどうかを利用者と決める（部門を1件でも作ると部門管理を使う扱いになり、期首残高の貸借の一致を部門ごとに見るか全部門の合計で見るかが変わる）。PSAと連携して使うときは、取引先・部門をPSAからの連携で作るのか、この手順で作るのかを先に利用者と決める（決めずに作ると重複する） |
| 3 | 移行元の資料を読み、対象の種類ごとに既存のマスタを読んで突き合わせる。コードの対応表・重複・欠け・既定の科目表との差を作る。読めない値や欠けた値は推測で埋めず、利用者に確かめる |
| 4 | 次の順に、**種類ごとに「投入計画を示して承認を得る→送る→読み戻して突き合わせる（§答え合わせ）」を終えてから次の種類へ進む**。部門・勘定科目（親の科目→補助科目）・セグメント・銀行口座 → 売掛金と買掛金の管理区分 → 取引先 → 期首残高 → 取引先別の開始残高・銀行口座の期首残高 → 固定資産 → 期中の月ごとの合計。後の種類は前の種類を作り終えてから決まる値を使うため、順を入れ替えず、計画を先にまとめて組まない（補助科目を作ると親の科目は仕訳に使えなくなり、期首残高は補助科目へ入れる。取引先のidは作ってから得られる）。期首残高のいまの値は、期首残高の計画を組む直前に、部門マスタにある部門だけ読む（無い部門のコードで読むと不要な見出しができる） |
| 5 | 1件ずつの呼び方は順に送り、失敗したらその場で止める（§途中で止まったとき・失敗したとき）。作った記録のidは、作ったときの応答から移行元のコードと対にした対応表に控え、利用者に渡すかファイルに残す（移行は会話をまたぎうる。次の会話ではこの対応表を読み込んでから続ける）。固定資産を作る前には、段3で読んだ既存の資産のコードとidも、対応表とあわせて残す。作る呼び方で502が返ったときの照合（§途中で止まったとき・失敗したとき）に使う |
| 6 | 全種類を送り終えたら、もう一度全体を読み戻して突き合わせる（§答え合わせ） |
| 7 | 検証用の法人で流したときは、結果を利用者に示し、本番の法人で段1から流すかを確かめる |
| 8 | 利用者に、事業年度の状態を画面で利用中へ切り替えるよう伝える。切り替えた後は期首残高と銀行口座の期首残高を直せないことを添える。取引先別の開始残高は、事業年度の状態を利用中へ切り替えた後もこの手順の呼び方で登録できるが、切り替えた後は送らない。状態の切り替えはこの手順では行わない |

## 読むと記録を作る呼び方

読み方の中には、読むと記録を作る・計算し直すものがある（どれがそうかは意味定義の `rule` が書く）。

- **承認の前（段3と、段4で各種類の計画を組むとき）に使ってよいのは、画面で開いたときと同じ記録を作るだけのもの**（期首残高を読むと空の見出しができる・固定資産の一覧を読むと月の締めの記録ができる）
- **取引先別の期首残高を読む呼び方は締めを作り直すので、承認のあとの読み戻しだけで使う**
- **銀行口座の期首残高は、意味定義が読み戻しに挙げる呼び方で読む。** 口座の月を作る呼び方は使わない

## この手順で作った取引先・銀行口座は画面で直せる人が限られる

ERPのMCPから作った取引先・銀行口座には外部連携の情報が付き、画面で直す・消すことは既定で許されない。画面で直せる・消せるのは、取引先なら管理者か取引先マスタの管理者、銀行口座ならマスタの管理者か管理者の権限を持つ人だけになる。投入計画にこのことを添える（§承認の単位）。部門・勘定科目・セグメント・管理区分・固定資産には、この制限は掛からない。

- 外部連携の情報があることを、PSAとの連携で作られた目印にしない。この手順で作ったものにも付く。意味定義が外部連携の情報をPSA連携の目印として書いていても、それで見分けない。PSA連携の取引先との重複は、段2の取り決めと段3のコードの突き合わせで避ける。この手順で作ったものかどうかは、段5で控えた対応表で見分ける

## 期首の残高は置き換えで入れる [REQUIRED]

期首残高・取引先別の開始残高・銀行口座の期首残高の3つは、足し込みでなく**置き換え**で入る。置き換わる範囲は3つで違う。

| 対象 | 置き換わる範囲 |
|---|---|
| 期首残高 | 送った部門の全科目。その部門の明細と開始残高の仕訳を消して作り直す |
| 取引先別の開始残高 | 送った取引先だけ。送らなかった取引先の値は残る |
| 銀行口座の期首残高 | 送った口座だけ。送らなかった口座の値は残る |

- **期首残高は、部門ごとに全科目を1回で送る。** 科目を分けて2回送ると、2回目が1回目を消す。部門は1つずつ順に送り、同時に送らない。送る前にいまの値を読み、消えるものを投入計画に示す（段3）。消えた開始残高の仕訳は送り直しても戻らない
- **取引先別と銀行口座の誤りは、送り直す一覧から外すだけでは直らない。** 誤って入れた取引先は、意味定義の `rule` が書く消し方で開始残高を消す。誤って入れた口座は、その口座に正しい値（0を含む）を明示して送り直す（口座の値を消す方法は未確認）。直したら全件を読み戻して照らす
- **送る前に事業年度の状態を確かめる。** 導入中でない期への送信は、拒まれるものと、拒まれずに書けてしまうものがある。どちらも送らない
- **送る前の検査は、意味定義の `rule` が挙げるものを全部通す。** 製品が拒まずに通すもの（無い科目のコード・入れない種類の科目・期首に開設されていない口座・取引先と科目の組み合わせの誤り）があり、通すと読み戻すまで気づけない
- **期首残高と、取引先別・銀行口座の残高は別の記録である。** 片方を入れても他方へ写らないので、両方を入れる

## 固定資産 [REQUIRED]

期首より前に取得した固定資産の取得は、期首残高に入っている。既定のまま作ると取得の仕訳ができ、期首残高と二重になる。

- **取得の仕訳を作らない指定を、意味定義の `rule` が書く組み合わせのとおりに必ず送る。** 指定の一部だけでは仕訳は止まらない
- **前期末までの償却の合計と、管理を始める事業年度で、期首の帳簿価額を入れる。** 償却方法・計上方法・部門は移行元に合わせて明示して送る（省くと既定の値や空が入り、償却の仕訳が作れなくなるものがある）
- **作ったら続けて償却の予定を作る。** 作らないと、移行後に償却の仕訳が立たない。標準の予定を読んでから送る。償却の予定を作る呼び方は既存の予定を消して作り直すので、段5で控えたidの資産（この移行で作った資産）にだけ送り、移行の前からある資産へは送らない
- **保存した償却の予定は読み戻せない。** 標準の予定を読む呼び方は、保存した予定でなく計算し直した予定を返す。償却の予定は、画面の償却の計画で確かめるよう利用者に頼み、確かめるまでは「未確認」と書く

## 期中に使い始めるとき

期首から利用開始日の前の月までを、月ごとの合計の振替伝票で入れる。振替伝票の登録はti-update `references/tsubaiso-erp-write.md` の条件（§当面の範囲 の、Atlasで引けないあいだは登録しない3つと、§POSTしてよい条件）に従い、承認だけを本書の §承認の単位（月ごとの全科目）に置き換える。同書の §振替伝票を登録・更新する の手順5は、AIが登録する振替伝票の外部連携の情報に、連携元のコードと、画面で直せる指定と画面で取り消せる指定を付けると定めている。移行の振替伝票にもこの3つを付け、付けることを投入計画に記載する。振替伝票を登録できない状態のあいだは、月ごとの合計を画面で入れるよう利用者に案内し、期首の残高までをこの手順で入れる。

段2で、次の2つを利用者と決める。

- **期首から利用開始日の前までに取得した固定資産。** 取得は期首残高でなく月ごとの合計に入る。固定資産として作るときも取得の仕訳を作らない指定を送り、取得価額の答え合わせの相手を利用開始日の前の月末の資産の科目にする（§答え合わせ）
- **期首から利用開始日の前の月までの償却。** 移行元のこの期間の償却は月ごとの合計に入る。償却の予定にこの期間の月が含まれると、画面で償却の仕訳を作ったときに二重になりうる（製品の扱いは未確認）。償却の予定の月を画面の償却の計画で利用者と確かめ、この期間の月の償却の仕訳は作らないよう伝える

## 答え合わせ [REQUIRED]

投入したら指示を待たずに行う。合わないものは、その種類の段3（既存との突き合わせ）からやり直し、計画を示し直して承認を得る。

| 対象 | 読み戻して比べるもの |
|---|---|
| マスタ | 一覧の件数とコードを、投入計画と移行元に照らす。投入計画に示した、既定の値が入る項目と区分や種類で決まる項目も照らす |
| 期首残高 | 部門ごとに、科目ごとの金額を移行元の期首の貸借対照表に照らす。借方と貸方の合計・明細の件数も照らす |
| 取引先別の開始残高 | 読み戻した全取引先を移行元に照らす（送っていない取引先に値が残っていないかも見る）。科目ごとの合計を、期首残高の売掛金・買掛金の科目に照らす。期中に使い始めるときは、期首残高に月ごとの合計を加えた、利用開始日の前の月末の残高に照らす |
| 銀行口座の期首残高 | 読み戻した全口座を移行元に照らす（飛ばされた口座と、送っていない口座に残った値が無いかを見る） |
| 固定資産 | 件数と合計を、期首残高の資産の科目に照らす。計上方法で比べる相手が変わる。間接法は取得価額の合計を資産の科目に、償却の合計を減価償却累計額の科目に照らす。直接法は帳簿価額の合計を資産の科目に照らす。期中に使い始めるときは、期首から利用開始日の前の月までに取得した資産の取得価額を、利用開始日の前の月末の資産の科目に照らす。償却の合計（直接法なら期首より前に取得した資産の帳簿価額）は期首残高の科目に照らす（期中の償却は月ごとの合計の側にあるため）。償却の予定は §固定資産 のとおり画面で確かめてもらう |

利用者には業務の言葉で示す。path・項目の名前・意味定義の名前を見せない（ti-core `references/output-discipline.md`）。取引先の外部連携の情報を読んだときは、同書 §ツバイソERPの個人の情報と連携の鍵 にも従う。金額は利用者自身のデータなので、会話の中で示してよい。

## 途中で止まったとき・失敗したとき

- **1件ずつの呼び方で失敗したら、その場で止める。** 続きを自分の判断で送らない。既存と突き合わせ直して、まだ入っていないものだけを投入計画に示し、もう一度承認を得る。利用者が中断したときも同じ
- **502のあとは送り直さない（償却の予定を作る呼び方は次の項）。** ツバイソERPの側では処理が済んでいることがある。少し時間を置いて読み戻し、入っていればそれを結果にする。固定資産なら、段2で確かめた利用開始日を含む年月を指定して（一覧はその月の末日までに取得した資産を返す。取得日の月を指定すると、期首より前に取得した資産ではその月の事業年度が無く、一覧が返らない）一覧を全ページ読み（ページ送りを止める条件は意味定義の `rule` が書く。返った件数だけで止めると、資産の数がちょうど1ページの件数の倍数のとき止まらない）、コードが移行元のコードと完全に一致する資産を探す（一覧にはコードの絞り込みが無いので、名前の絞り込みの条件にコードを指定しない）。その資産のidが、段3で読んだ既存の資産のidのどれとも一致しないことを確かめてから控え、償却の予定の作成まで進める。コードが一致する資産が1件に決まらないとき（見つからない・複数ある・一覧を読めなかった）・その資産のidが既存の資産のidと一致するときは、償却の予定を作る呼び方を送らずに止める（取り違えた資産へ償却の予定を作る呼び方を送ると、その資産の償却の予定と仕訳が削除され、元に戻せない）。読み戻しても見つからないときは、画面で有無を確かめてもらい、無いと確かめてから承認を得直す。作る呼び方で送り直すと二重に作られる
- **償却の予定を作る呼び方だけは、失敗・502のあとに送り直す。** 既存の予定を消してから作るので、失敗した資産は予定が消えたまま残ることがあり、送り直しても二重にはならない。承認済みの計画の範囲で、原因を直した全件（期首の償却分を含む）を同じ資産へ送り直し、画面の償却の計画で確かめてもらう
- **期首残高・銀行口座の期首残高を送って404が返ったら、状態による拒否とみなして止める。** 事業年度の状態を読み直し、呼び方を組み替えて送り直さない
- **422・403は、返った理由を業務の言葉で伝え、同じ内容で送り直さない。** 理由の文言が無い422が返ることもある。そのときは送った内容を意味定義の必須の項目・拒む条件と照らし直し、直せる誤りが見つからなければ、利用者に伝えてツバイソのサポートへの問い合わせを案内する
- **401は、つなぎ直したあとに条件3をやり直してから続ける。** 参照と共通の扱い（401・500・別の法人）はti-reference `references/tsubaiso-erp-web-api.md §失敗したとき` に従う

## 検証用の法人で先に流す [REQUIRED]

本書の手順は、PSA/IMAのサンドボックスのような本番の複製を前提にしない。**検証用の法人を別に用意し、その法人へ接続した状態で、本番と同じ手順を1回流して答え合わせをする。** 本番の法人で試しに流すことはしない。検証用の法人を用意できないときは、本番の法人へは流さず、用意を利用者に頼む。

- 期首残高は、送り直しても消えた開始残高の仕訳は元に戻らず、0を送った科目にも0の明細が残る。検証用の法人でも、期首残高を試すのは、導入中の期があり、まだ明細の無い部門にする
- 検証用の法人で作った取引先・銀行口座の後始末は、管理者などの権限を持つ人が画面で行う（§この手順で作った取引先・銀行口座は画面で直せる人が限られる）
- 検証用の法人で確かめられるのは、手順・項目の対応・送る順・送る前の検査が通ることまでで、本番の法人の設定（事業年度・部門管理の有無・課税方式）が違えば結果は変わりうる。本番へ流す前に、手順の段2の前提を本番の法人で確かめ直す
