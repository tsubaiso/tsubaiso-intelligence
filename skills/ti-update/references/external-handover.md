# ERP の外にあるものとのあいだの受け渡し

仕事は ERP の中だけで完結しない。注文書はメールで届き、仕様は文書に、やり取りはチャットにある。逆に ERP の中の採算・与信を取り出し、外の資料と突き合わせて次の判断を組み立てる場面もある。**AI は ERP の外側にいるので、この行き来を AI 自身が担える。** ただし作法が要る。

## 2つの向き

| 向き | 実体 | 担い |
|---|---|---|
| 外 → ERP | 文書・ファイルから取引レコードを作る／更新する | `input-support.md`（本スキル） |
| ERP → 外 | 参照・集計の結果を外の作業へ渡す | ti-reference（参照・集計） |

**本 reference は、2つの向きに共通してかかる作法だけを定める。** 各向きの手順そのものは上記へ委ねる（ここに手順を再掲しない）。

## 守ること [REQUIRED]

1. **出所を残す。** ERP へ入れたものは、どの文書・どのファイルのどこから来たかを人が辿れる形で示す。突合検証（`input-support.md`）はこのために行う。
2. **取り出したものに時点を付ける。** ERP から外へ渡した数値は、渡した時点のもの。締め前・承認前のものが混じるので、**いつ時点の値かを必ず添える**。外の資料に写った瞬間に、その数値は ERP の更新から切り離される。
3. **持ち出しの範囲は本人の権限内。** 参照できないデータは外へも出せない。**外へ渡す経路を通ることで権限が緩むことはない。**
4. **外にあるものを ERP の正としない。** 外の資料の値と ERP の値が食い違ったとき、どちらが正かは人が決める。**AI が黙って上書きしない。** 食い違いは差分として提示する。
5. **システム間を「つないだ」と言わない。** ここで行っているのは AI による都度の受け渡しであって、恒常的な連携基盤ではない。**定常運用に載せるなら実装形態の判断が要る**（ti-lifecycle）。利用者へもこの区別を明示する。

## 詰まりどころ

| 症状 | 対処 |
|---|---|
| 同じファイルを二度取り込んだ | 突合で既存レコードとの重複を先に検出する（`input-support.md`）。取り込み後の検出は消込済み・承認済みだと戻せない |
| 外の資料の粒度が ERP と合わない（明細の束ね方・単位・期間） | 合わせ方を人に確認する。**推測でマッピングしない**（`input-support.md` の「推測で埋めない」と同じ規律） |
| 外へ渡した数値が独り歩きした | 2 の時点表記が抜けている。渡す側の作法として先に付ける |
| 外部システムのデータを直接読みたいと求められた | 本 reference の射程外。AI が受け取れる形（ファイル・文書）にしてもらうか、実装形態の判断（ti-lifecycle）へ送る |

## 記録

受け渡しそのものはレコードを持たない。**ERP 側に残るのは入力支援が作ったレコードとその作成者だけ**で、「どの外部資料から来たか」は本 reference の 1（出所を残す）で人が辿れる形にしておく以外に担保が無い。この点は利用者へ伝えておく。
