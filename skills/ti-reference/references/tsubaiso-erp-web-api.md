# ツバイソERPのデータを参照する（ERPのMCP）

本書の「ツバイソERP」は、会計の製品（会計・販売・給与など）を指す。SalesforceのパッケージであるツバイソPSA/IMAとは別の製品で、ti-updateが「ERPの外にあるデータ」と書くときのERP（PSA/IMAを指す）とも別のものである。利用者へ見せる文では「ツバイソERP」と呼び、初出は「ツバイソERP（会計）」と書く。

登録・更新はti-update `references/tsubaiso-erp-write.md` が持つ。本書は参照・集計だけを扱う。

## いつ読むか

- ツバイソERPのデータを参照・集計する依頼を受け、ERPのMCPのツール `call_web_api` をそのセッションで最初に呼ぶ直前
- `call_web_api` が200番台以外を返した瞬間、またはツールの呼び出しそのものが失敗した瞬間（§失敗したとき）
- Atlasのレシピの本文に `source:` の節があった瞬間（§レシピの読み方）

## 前提

- **ERPのMCPが接続済みであること。** ツールは `call_web_api(path, method, params)` の1本だけで、参照も書き込みも同じツールで行う。接続の手順は、ツバイソヘルプデスクの記事「ClaudeなどのAIクライアントからツバイソERPのデータを扱う」が正本（案内はti-rollout）。記事をナレッジで引けないときは、手順を推測で組み立てず、引けなかったことを伝えてツバイソのサポートへの問い合わせを案内する
- **Tsubaiso Atlas MCPが接続済みであること。** どのpathで何が取れ、返る項目が業務で何を意味するかは、Atlasの意味定義が持つ
- **1つの接続で扱える法人は1つ。** 接続したときに利用者が選んだ法人のデータだけが返る。接続の有効期限は最長1時間で、それより早く切れることもある
- **見える範囲は、接続した本人のツバイソERPの権限どおり。** 画面で見えないデータはAIからも見えない

**Atlasを引けないとき（未接続・403）は、ERPのMCPを推測で呼ばない。** ツールの説明は「どのpathが使えるかは画面のURL・資料を参照」としか言わない。画面のURLやAPIドキュメントから自分でpathを組み立てると、当月分だけを返す一覧を全期間と読む・別の業務から作られた仕訳を取りこぼす、といった誤りがエラーなく通る。利用者にAtlasの接続と利用契約の確認を促し、参照を保留する。403の確認先をPSAの契約に限らない（ツバイソERPだけを使う組織もある）。

**Atlasの `呼び方:` に無いpathは、GETでも呼ばない [REQUIRED]。** ツバイソERPには、GETで呼んでも登録が起きる画面のpathがある。接続は画面のpathにも届くので、GETであることは安全の根拠にならない。Atlasを引けても目的の呼び方が無いときは、参照できないことを利用者に伝える。

## 手順（Atlas → ERPのMCP）

1. **地図を引く** — `atlas_domain_index`。ツバイソERPのオブジェクトは、`meaning_short` が「ERP」で始まる。PSA/IMAのオブジェクトと同じドメインに並ぶので、`meaning_short` で見分ける。ツバイソERPのオブジェクトの名前には名前空間が無いが、顧客が追加したメタデータではない（SKILL.md §顧客が追加したメタデータの意味を使うとき の対象外）
2. **呼び方を引く** — 対象のオブジェクトに `atlas_explain(target=…)`。`target` には索引の `api_name` を渡す。`rule` の先頭に、使うpathごとに `呼び方: {GETかPOST} {path}（{必須の絞り込み}・{ページ送りの有無}）。` の文が並ぶ。参照にはGETの文を使う。明細の集まり（名前にドットを含むもの）は自分の呼び方を持たないので、親のオブジェクトの呼び方で取得する
3. **レシピがあれば使う** — `atlas_recipe`。ツバイソERPのレシピは §レシピの読み方 のとおり読む。レシピの探し方と `not_found` の扱いはSKILL.md §`not_found` を受けたら、「無い」と書く前に引き直す と同じ
4. **呼ぶ** — `call_web_api` にpath・method・paramsを渡す（§呼び出しの組み立て）
5. **読む** — 応答の `body` を、`atlas_explain` の項目の意味で読む（§応答の読み方）
6. **返す** — 業務の言葉で返す。path・リソースの名前・項目の名前・レシピ名を、利用者へ見せる文とファイルに書かない（ti-core `references/output-discipline.md`）。ツバイソERPの画面のURLは、意味定義に組み立て方が無いので推測で組み立てない

## 呼び出しの組み立て

| 渡すもの | 中身 |
|---|---|
| `path` | `呼び方:` のpathの先頭に `/` を足し、`:` で始まる部分を値に置き換える（例: `{リソース}/show/:id` → `/{リソース}/show/123`） |
| `method` | 参照は `GET`。ツールはGETとPOSTだけを通し、ほかは400を返す |
| `params` | GETでは、キーと値が1組ずつクエリ文字列に付く。値は文字列・数値などの平らな値だけにする（配列や入れ子の値は1つの文字列になり、正しく送れない）。POSTでは本文になる |

- **参照はGETで行う。** POSTは参照でも書き込みでも同じツールを通り、ツバイソERPで登録・更新・削除まで届く。POSTを使うのはti-updateの書き込みの手順だけにする
- **必須の絞り込み**（`呼び方:` の括弧の中）は必ず渡す
- **年月を受ける一覧は、年と月を両方指定する。** 年月を省くと当月分だけが、年だけを渡すとその年の1月分だけが、どちらも通知もエラーも無く返る。複数の月は月ごとに呼ぶ
- **形式を指定しない。** JSON以外（CSV・PDF・HTML）で返る呼び方をしない。JSON以外の本文は、長いと途中で切れて返る

## 応答の読み方

- 戻り値は `{status, body}`。`status` はツバイソERPのHTTPステータスをそのまま返す。200番台以外は §失敗したとき へ
- **200番台でも、`body` がJSONでなく文字列（画面のHTMLなど）なら失敗として扱う。** 呼び方を引き直す。文字列の本文を結果として読まない
- `body` の形は2つ。(a) 一覧がそのまま配列で返る (b) 封筒 `{records: […], metadata: {page, per_page, total_pages, total_entries}}` で返る。封筒ならレコードは `records` にある
- **ページ送りのある一覧は最後まで送る。** `呼び方:` の括弧が「ページ送りあり」なら、`page` を1から `metadata.total_pages` まで送り、集めた件数を `metadata.total_entries` と照らす。1ページ目の件数（既定の件数）を全件と読まない。1ページの件数（`per_page`）は、意味定義に上限が書かれていればその値まで上げてよい
- **金額の税込・税抜は、項目ごとに意味定義で確かめる。** PSA/IMAの既定（税込）をツバイソERPに当てはめない
- **日付の軸は意味定義で確かめる。** どの日付で年月を切るかは、オブジェクトの `rule` と項目の意味に書かれている
- **件数を断定するときは、期間と絞り込みを添える**（例:「10月の振替伝票は12件」）。期間を指定せずに得た件数を全件と書かない
- **応答に出ても意味定義に無い項目は、名前から業務語へ読み替えて条件や結果に使わない**（SKILL.md §describeが返す項目の読み方 と同じ扱い）

## レシピの読み方

Atlasの `atlas_recipe` は、ツバイソERPのレシピも `soql` の欄に入れ、種類を `soql` として返す。**本文に `source:` の節（`endpoint` と `method` を持つ）があれば、SOQLではなくツバイソERPの呼び出しとして読む。Salesforceの接続へ投げない。**

| 本文のキー | 扱い |
|---|---|
| `source.endpoint` | `path` にする（先頭に `/` を足し、`:` で始まる部分を `path_params` の値で置き換える） |
| `source.method` | `method` にする |
| `source.path_params` | pathの `:` で始まる部分に入れる値。`<YYYY>`・`<MM>` などは依頼に合わせて充当する |
| `source.query` | `params` に渡す |
| `source.records` | 応答が封筒のとき、レコードの配列を指すキー |
| `flatten`・`project`・`group_by`・`aggregate`・`order_by` | 応答に当てる手順で、集計は手元で行う。`<response>` は `body`（`records` があればその配列）。`- a in b` は配列bの各要素をaと呼んで展開する。`[:year]`・`[:month]` は日時の年・月を取る |
| `#` で始まる行 | 注記。読み落とさない（例: 借方と貸方を別に集計する・複数の月は月ごとに呼ぶ） |

## 失敗したとき

| 返り | 意味 | すること |
|---|---|---|
| 400（ERPのMCPが返す） | GET・POST以外のメソッドを渡した | 呼び方を引き直す |
| 300番台 | 別の場所への転送。呼び方の誤りか、接続の問題 | 転送先を追わない。呼び方を引き直し、直らなければ利用者に伝える |
| 401、またはツールの呼び出しそのものが認証の失敗で返る | 接続が切れた（有効期限は最長1時間で、早く切れることもある） | 同じ呼び出しを繰り返さない。利用者に、コネクタを接続し直すよう案内する |
| 403 | 本人の権限が無い、または締めなどの制限 | 権限を持つ人・制限の解除を利用者に案内する。権限の追加を推測で提案しない |
| 404・422 | pathか引数の誤り（422は締めなどの制限のこともある） | 呼び方を引き直す。直らなければ、返った内容を業務の言葉で利用者に伝える |
| 500 | ツバイソERPの内部の失敗 | 繰り返さず、利用者に伝える |
| 502 | ツバイソERPへつながらない、または応答が時間内に返らない | 年月・件数などで絞って1回だけ呼び直す。続けて失敗したら利用者に伝える |
| 別の法人のデータが要る | 1つの接続は1法人 | コネクタを接続し直し、法人を選び直すよう案内する |

書き込み（POST）の失敗は、ti-update `references/tsubaiso-erp-write.md §失敗したとき` を本表より優先する。

> - **依存事実**: ERPのMCPが `call_web_api` の1本だけを公開し、GET・POST以外に400を返し、ツバイソERPのステータスを素通しし、接続できないときと読み取りの時間切れに502を返し、JSONでない本文を文字列で返すこと。接続の有効期限が最長1時間で、1つの接続が1法人に結びつくこと。GETで登録が起きる画面のpathがあること。Atlasの `atlas_recipe` がツバイソERPのレシピを `soql` の欄で返すこと（いずれも開発チームの変更で変わりうる）
> - **実証日**: 2026-10-29（ERPのMCPのコードとツバイソERPのコード、Atlasの `atlas_domain_index`・`atlas_explain`・`atlas_recipe` の応答で確かめた。300番台の転送の扱いは実機で確かめていない）
> - **実証コマンド**: `atlas_recipe` にツバイソERPのレシピの名前を渡し、返りの `kind` と、本文が入る欄を見る。`atlas_explain` に振替伝票のオブジェクトの名前を渡し、`rule` が `呼び方:` で始まることを見る。`atlas_domain_index` で、ツバイソERPのオブジェクトの `meaning_short` が「ERP」で始まることを見る
