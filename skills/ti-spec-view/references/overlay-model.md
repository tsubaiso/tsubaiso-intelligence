# テナント依存の意味層とデータモデル・IP保護2軸

構造層（`structure-enumeration.md`）は「何があるか」を出すが「業務的に何を意味するか」は出ない。意味付けは顧客固有＝テナント依存で、共通の意味定義（テナント非依存IP）とは**物理的に別系統**に持つ。この意味層をここで管理する。

## 不変条件（共通IPとの分離） [REQUIRED]

- **共通の意味定義（テナント非依存IP）**はサーバー基盤側に保持し、顧客へ配らない。
- **顧客固有の意味付け（テナント依存）**は顧客の情報として扱い、共通IPとは**別の物理ストア**（顧客の組織）に持つ。
- **実行時結合**: 可視化は「構造＋共通意味＋顧客固有の意味付け」をAPI名で実行時に重ねて構成する。重ねるのは利用者側の実行環境で、意味付けの本文をサーバー基盤へ送らない。
- **非焼込**: 可視化ビューに共通IP本体（意味定義の説明文）を顧客org内へ永続化しない。保存するのはAPI名骨格＋顧客固有の意味付けのみで、共通IP由来の説明文は含めない。
- **昇格は抽象パターンのみ**: 顧客固有の値・命名・実データに紐づく意味付けは共通IPへ昇格しない（`ip-governance.md`）。

## 格納先（カスタムメタデータ型に一本化）

顧客固有の意味付けの格納先は、tb_PSAに同梱するカスタムメタデータ型（以下「意味付けの型」）だけとする。かつての二層（高頻度に書くカスタムオブジェクトと、確定値を持つスナップショット）は廃止した。

- **意味付けの型の1レコード＝1つの意味付け**で、共通の意味定義の1レコードと同じ構造（区分・対象・見出し・意味・ルール・構造化値・ドメイン・役割タグ・確認日・有効）を持つ。これに、意味付けの型だけが持つ書き手・確信度・実装しているメタデータ・関係するメタデータ・関係するオブジェクトを加える。同じ構造にすることで、スキルは製品の意味と同じ区分の一覧に並べて扱える。
- 型名・項目名・項目の型と長さはツバイソの開発チームの詳細設計で決まる。**本書に型名・項目名を記載しない。**
- 書くのは、管理者の権限を持つ人か、その権限で動作するAIに限る。AIが書くのはti-metadataの配備（同じ配備に意味付けのレコードを含める）・取り込み・確認一覧の回答の登録だけとする。一般の利用者との会話で得た意味付けは組織に書かず、確認一覧に加える。
- 説明欄・ヘルプテキストは格納先にしない。記入済みの本文は、意味付けの型へ取り込む元の文面として扱う。AIは既存のメタデータの説明欄を書き換えない。

**いまの段階（Phase 1）では、意味付けの型をまだ読み書きしない。** 説明欄・ヘルプテキストを読む読み方と、確認一覧はti-core `references/customization-meaning.md` が正本で、本スキルもそれに従う。意味付けの型を読む手順・取り込み・登録・鮮度の判定は、型の詳細設計を受けて加える。

## 書き手と確信度

書き手（顧客記述／推定）と確信度の値の定義は、ti-core `references/customization-meaning.md` §属性行 が正本で、意味付けの型でも同じ値を使う。

- 書き手は、誰が書いたか（提供側・パートナー・顧客）ではなく、**顧客の管理者が本文を確認したかどうか**で決まる。推定の意味付けは、顧客の管理者が本文を確認した時点で顧客記述へ改める。
- **既存の意味付けを上書きしない。** 顧客記述の意味付けは、顧客の管理者の確認なしに書き換えない。

## IP保護2軸（可視化の必須前提） [REQUIRED]

可視化は次の2軸を必ず守る。片方だけを見て「逆向きだから安全」と結論しない。

- **軸1: ツバイソIPの外流出の不在** — 共通の意味定義を顧客へ渡さない。可視化は顧客固有の意味付けと構造を扱い、共通IPを顧客可視範囲に持ち込まない（非焼込）。
- **軸2: 当社（サーバー側）は顧客データを受け取らない** — 当社・パートナーが顧客カスタマイズを閲覧する経路では顧客org構造データが当社側に渡りうる。閲覧データを当社環境に**非永続＝都度取得・非滞留**で保つ。製品の意味と重ねる目的であっても、意味付けの本文をサーバー基盤へ送らない。

軸2の担保（閲覧経路・意味付けの共通化）は `ip-governance.md` で扱う。

**書込前ゲートの射程 [注意]**: 意味付けの型のレコードはメタデータの配備でしか書けない（通常のレコードの作成・更新の経路を持たない）。書くときはti-metadataの配備としてti-coreの安全ゲート（`safety-gate.md`・メタデータの書込専用）を通す。参照スキル（ti-reference）が持つレコードの書込前ゲート（作れない工程の検出・参照先の有効条件チェック）は、意味付けの型の書き込みには適用しない。両ゲートは射程が別で、取り違えない。
