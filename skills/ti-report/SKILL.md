# ti-report — 帳票カスタマイズ

> **ベータとして先行提供している機能です。** 記述が変わることがあります。扱いは ti-core の `references/beta-status.md` を参照してください。

PSA/IMA を使う顧客の帳票を、自社のレイアウト・項目に合わせてカスタマイズする作業を支援する**能力スキル**。持つのは帳票固有の**中身**（テンプレの差込DSL・データの流し込み・意味定義マッピング・押印/DRAFT判定・「どの権限/配置/項目/資産が要るか」のauthor・反復調整・帳票設計書/仕様書の継続修正サイクル・美観の原則）。**メタデータを届ける機構は持たず**、配備は ti-metadata の機構へ渡す。

本書は薄い索引に徹する（詳細は必要な reference だけを読む方式）。手順の実体は各 reference にある。

## このスキルが持つもの・持たないもの

| 持つ（帳票の中身） | 持たない（機構＝委譲先） |
|---|---|
| テンプレの差込DSL・流し込み・意味定義マッピング | メタデータ配備の実行（取得→差分→検証→反映）＝ ti-metadata |
| 押印/DRAFT判定・共通の出力ボタンのシェル規約（実体＋IFはローカル） | 文書→レコードの取込・入力支援＝ ti-update |
| 配置に要る権限・項目・資産・レイアウトの author | 参照先の有効条件チェック・作れない工程の検出＝ ti-reference |
| 反復調整・帳票設計書/仕様書の継続修正サイクル・美観の原則 | 導入プロジェクトの工程進行＝ ti-onboarding |

中身は本スキル、機構は能力スキル。この主従を崩さない。押印/DRAFT判定と共通の出力ボタン規約は現状の利用者が帳票のみのため本スキルローカルに置き、2つ目の利用者が現れた時点で ti-core へ昇格する（それまで非昇格）。

## 原則

- **中身はここ、機構は能力スキル**。テンプレ・マッピング・押印判定・authorは本スキルが持ち、メタデータ配備の実行は ti-metadata へ委ねる。
- **本書は薄く保つ**。手順・チェックリストは reference に置き、SKILL.md は索引に徹する。
- **道具と型は標準・あてはめは顧客ごと**。美の原則・DSL・設計書/仕様書のフォーマットは全顧客共通、ブランド具体値・各帳票の項目/指示の中身は都度あてはめる。
- 利用者向け出力に内部識別子（API名・SOQL・レコードID）を出さない（ti-core 群Aの出力規律に従う）。項目マッピング設計書は管理者・コンサル向けの技術ドキュメントとしてのみ源データ項目のAPI名を扱う。
